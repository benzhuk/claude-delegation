## Rulings on the three deviations

1. **Change 3 allows deleting or moving secret-shaped files everywhere: not as in the brief.** Change 3 limits it to the scratchpad, the temp folders and `.vercel`. The builder followed the brief's governing line ("the guard refuses sight only"). For sight it is neutral: rm and mv print nothing. The one sight effect, cp to `/dev/stdout`, is closed by N4. Integrity is a real loss against main: `rm`/`mv` of `~/.config/chezmoi/key.txt` (the age identity every encrypted dotfile depends on) and of `~/.ssh/id_*` are now allowed. Main denied them (P51 and P52 show the same flip for claude.env). Ben decides. Either accept it because the guard is a sight guard, or restore the brief's scope for `rm|mv|shred|unlink|Remove-Item` with an operand list limited to the three locations. If he accepts, record that the age key has no guard.
2. **Bare `vercel env ls` refused and wrapped: in the brief, in effect. Keep it.** The installed CLI v50.13.2 `dist/index.js:183770-183772` renders plain variables as `ellipsis(singleLineValue, 19)`, and :183720 puts the full plain value in `--format json`. Both break the brief's rule against any substring beyond an 8-character fingerprint. Ben's addendum is met: names stay listable through `secret-tool.sh ls --vercel` (names only; the awk keeps only line-anchored `"key"` lines from `JSON.stringify(..., null, 2)`, and a value cannot start a line because newlines are escaped), and local `secret-tool.sh ls` prints names and lengths only. Both are tested.
3. **Change 1 is proven only on a fake HOME, and PowerShell is uncovered: not as in the brief, forced, and accepted for now.** The brief's proof (a fresh Bash tool call in a new session) needs `chezmoi apply`, which the brief's own rules hold until Ben's word. Until that proof runs after apply, change 1 is unproven and must not be reported as done. Discriminating check after apply, in a new terminal and a new session: Bash tool `test -n "$ANTHROPIC_API_KEY" && echo set=yes || echo unset`. The guard allows that form and it prints no value. Expect `set=yes`. `unset` means the Bash tool runs an interactive shell (`bash -i` ignores BASH_ENV, measured) or a shell started before the user variable existed.
