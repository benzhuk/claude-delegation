### N3: MEDIUM. The heredoc quote parity counts `"` inside single quotes and comments, and the comment stripper runs first and leaves a `\"` behind
G:1388-1389, G:1399-1403, G:1423 (my r2 patch, applied verbatim), and G:1950. Main denies every row:
- **H03:** `echo '"'; echo "x; cat > f <<'EOF'` / `$(cat SECRET)` / `EOF"`

- **H07:** `# a " quote`, then the same fake heredoc.
- **Q12:** the same with a tab-indented comment.

An odd `"` outside a double-quoted string flips the parity, so the fake `<<` inside the real double-quoted string looks unquoted. Its `$(cat SECRET)` body is then blanked before the substitution bailout runs. For H07 and Q12 there is a second cause: G:1950 runs `strip_shell_comments` before the heredoc scan. That stripper stops at a backslash, so `# a \" quote` becomes `\" quote` and the quote looks real.

Fix: the awk hunks in the patch replace `dqn` with `qscan`. It is a shell quote-state scanner over the JSON-escaped text, with these rules:
- `\"` toggles the double quote.
- `\\` escapes the next shell character.
- A `'` outside double quotes opens a single-quoted string. `$'` opens an ANSI-C string, where `\\` escapes.
- A `#` at a word start outside quotes ends the line. Word start means after a space, `; & | ( ) < >`, a JSON `\t`, the JSON opening quote, or line start.

A `<<` inside a string or a comment is not a heredoc. G:1950 is reordered so the heredoc scan sees comments intact and comments are stripped after it.
