# Codex-led build loop: facts for a future spec (read-only, 2026-10-01)

Paths are relative to the repo. BL = skills/team-build/references/build-loop-workflow.js, BLT = its .test.mjs. No suite run, nothing committed, no secret read. Web docs were fetched from developers.openai.com on 2026-10-01 (not version-pinned to the installed CLI).

## 1. The loop-state file lane 67 shipped
- Path rule: `<dir of recordPath>/<work-id>.loop-state.json`, work-id = record file name minus `.record.md`; a relative recordPath is resolved against `integrationWorktree` (BL:567-571, 303-319; BLT:1999 gives `/repo/wt-integrate/docs/work/wr-x.loop-state.json`, BLT:2007/2011 absolute and drive-letter). Enabled only when `recordPath` is given; without it no state call is made (BLT:1978-1990). Declared at BL:46.
- Fields (stateSnapshot, BL:586-597): `version` (1), `baseSha`, `specPath`, `phase` (last phase written: Setup, Build, Fix, Review, Integrate, Seam, Accept), `territories[]`, `integrator`, `seam`, `setup`, `acceptance`.
  - territory row (BL:580): `id, phase, sha, verdict, rounds, findingsPath, blocker` (BLT:2023 pins the exact row).
  - integrator (BL:1012): `verdict, headSha, reportPath, failedGate, territory, approvedKey` (approvedKey = `id@sha7` list of approved territories, BL:989).
  - seam (BL:1143): the seam result plus `integrateHead`. acceptance (BL:1239-1241): `{skipped}` or `{reportPath, verdict, integrationHead}`. setup: the Setup stage's return (worktrees, branches, brief paths, BL:107-130).
  - NOT in the file: the second-host result (returned only, BL:57, 1246-1272) and the `agentMinutes` deadline.
- Resume rule (BL:640-659, 798-820, 996, 1040): file used only if `version===1` and baseSha and specPath match the args. Territory APPROVE (no blocker), or NEEDS_FIXES with findingsPath, at a valid sha resumes as `startFrom`; integrator PASS over the same approvedKey and seam APPROVE at the same integrate head are skipped; an explicit `startFrom` in args wins.
- Who writes it: NOT the script (it has no fs, BL:557-560). A Sonnet `delegation:runner` agent per phase is told to write the JSON text verbatim (BL:599, 626); writes coalesce, territories do not await them, a failed write is logged and ignored (BL:608-632, BLT:2040-2060). One more Sonnet runner reads it at launch (BL:640). So each state write is a model call.
- Decides: the file is plain JSON with no Claude-specific field; any writer (a script, a Codex lead) can produce or read it. Its values (APPROVE/NEEDS_FIXES/BLOCKED/PASS, shas, report paths) mean the same on any host.
- Other lane-67 pieces: per-agent deadline is prompt-level only, `agentMinutes` default 45 (BL:42-43, 210-225; the Workflow API has no per-agent limit). Accept refuses a record with no `Workflow:` line when Spec-from is on/after WORKFLOW_FROM; accepts `<run id>` or `none, <reason>` (scripts/work-record.mjs:167-204). The lane-67 spec "Not in scope" names this job: docs/specs/build-loop-fed-67/spec.md ("must reuse this lane's state file as the shared contract, not a host primitive").
- Portability: the script body uses only five host hooks, `agent, parallel, phase, log, args` (BLT:316 runs it in an AsyncFunction with stubs; `pipeline` never called, `budget` unused, one `parallel(` at BL:967). `agent(prompt, {agentType, model, schema, phase, label})` must return a schema-shaped object or null. agentType/model are Claude names (`delegation:builder` sonnet, `delegation:reviewer` opus, `delegation:runner`/`integrator` sonnet; BL:884, 990, 1198). The script is mirrored at `~/.agents/skills/team-build/references/build-loop-workflow.js` (listed this session).

## 2. What Codex offers on this machine
- `codex --version` = codex-cli 0.159.3 (the brief and docs/model-tiers.md:97 say 0.154; native-use.md:179 saw 0.156.1). `claude --version` = 2.1.287.
- `codex exec` (from `--help`): `-m/--model`, `-s/--sandbox read-only|workspace-write|danger-full-access`, `-C/--cd`, `--add-dir`, `--worktree`, `-p/--profile` (layers `$CODEX_HOME/<name>.config.toml`), `-c key=value`, `--json` (JSONL: thread.started, turn.*, item.*, error), `--output-schema <file>` (final answer must match a JSON Schema), `-o/--output-last-message <file>`, `--ephemeral`, `--ignore-user-config`, `--ignore-rules`, `--skip-git-repo-check`, `--approve-for-me`, `--dangerously-bypass-approvals-and-sandbox`, `--dangerously-bypass-hook-trust`; subcommands `resume`, `fork`, `review`. No `--agent`/role flag. Prompt from arg or stdin. Per docs, an action needing new approval in non-interactive mode fails back to the parent.
- Hooks fire in `codex exec` (skills/multi/SKILL.md:62). Installed `~/.codex/hooks.json` keys, read this session: SessionStart, UserPromptSubmit, PostToolUse, Stop, Interrupt, PreToolUse (repo wiring hooks/codex-hooks.json:1-9; delete guard on PreToolUse Bash only). Docs list 11 events incl. SubagentStart, SubagentStop, PreCompact, PostCompact, SessionEnd (hooks page). A Stop hook returning `decision: block` makes Codex continue, with the reason as a new user prompt (hooks page, Stop section). The repo does not use that.
- Native subagents: feature `multi_agent` stable/true in `codex features list`; `multi_agent_v2` stable/false (not investigated). The lead spawns through the model tool `multi_agent_v1.spawn_agent` with a dynamic `agent_type` enum built from `~/.codex/agents/*.toml` and `.codex/agents/*.toml` (docs/work/evidence/codex-custom-role-native-review.md:15-31; codex-native-child-proof.md). It spawns only when asked or when a skill/AGENTS.md says so (subagents page). Model resolution: role-file `model` wins; else explicit spawn value, else `[agents].default_subagent_model`, else the parent (subagents page). docs/model-tiers.md:90 still says per-call override "unverified"; the page says an explicit spawn value is honored, so that line is stale. Shipped roles: builder/integrator/runner gpt-5.6-terra workspace-write, reviewer gpt-6-astra read-only (codex/README.md:8-12). `~/.codex/config.toml`: `multi_agent = true`, default model gpt-6-astra, effort high. Cap: `agents.max_concurrent_threads_per_session` (legacy `max_threads`; model-tiers.md:98 says default 6 at 0.154). Children inherit the parent turn's live sandbox/approval overrides even if the role file differs (subagents page).
- Context: a child runs in its own thread and rollout file; the page says subagents "return summaries ... instead of raw intermediate output" and that Codex "waits until all requested results are available, then returns a consolidated response". Children are Codex models only; "more tokens than comparable single-agent runs" (subagents page).
- `codex queue --thread <id|name> --message <text>`: stores a message the session runs as its next turn, only after its current turn ends (skills/multi/SKILL.md:123; help output). It wakes a lead; it does not drive a loop. `codex agents` browses sessions on the shared app-server daemon. `/goal` (feature `goals` stable/true; slash-commands page) sets a persistent target; a tracker with no phases or state file.
- `~/.agents/skills` mirror: has team-build (references/, scripts/ incl. review-run.mjs), multi, delegate and others. review-run.mjs runs a real `claude -p` Opus reviewer for a Codex lead, claims `<report>.identity.json` first, exits 0-7 (skills/team-build/scripts/review-run.mjs:1-24).
- `claude -p` offers `--json-schema`, `--output-format`, `--model`, `--agent/--agents`, `--session-id`, `--permission-mode`, `--max-budget-usd`, `--allowedTools/--disallowedTools` (claude --help).
- How the Codex lead ran lane 40 (record docs/work/wr-2026-09-29-knowledge-triage.record.md; docs/specs/knowledge-triage-40/territories.md:4-7): lead gpt-6-astra; T1 "Sonnet builder", T2 independent test author, T3 probe runner; Opus review-run for spec red-team and code review (13 sidecars, census-execution-report.md:31); native children on gpt-5.6-sol. Census (record:220-226, 235, 67-75): lead 117,309,036 tokens of which 114,433,536 cache read, 492,485 output; sol children 77,532,936; 58 subagent files; 19 lead turns, 906 counted responses, 7.13 h; top-tier tokens per build 196,423,342. Its own sources call out as costly: four review-run fix rounds and repair cycles (bearings-assessment.md:21,30,43), guard refusals that blocked probes and builders (record Log lines 21:16, 21:36, 21:53), and unattributable stalls (record Gap paragraph). The cost shape is context re-read over 906 responses, not output. How the Sonnet builders were launched is not stated in what I read; the census report treats them as shell-launched.
