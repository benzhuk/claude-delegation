### F1: HIGH. FP3 pass-along stripping lets through a printed alias of the whole environment (reopens red-team H3)
G:692-695. The print-context gate (`has_secret_print_context`) only looks for a print verb before the reference. Two shapes get through:
- Rule 2's `env` has no left word boundary, so the plain assignment `const env = process.env;` is treated as a pass-along.
- Rule 1 blanks any spread.

So `node -e "const env = process.env; console.log(env)"` and `const e = {...process.env, X: 1}; console.log(e)` are now allowed. Main denies both, because a bare `process.env` followed by `;` or `}` trips has_env_dump. This is exactly the one-hop shape that has_tainted_print was added to close (H3, round 6), and it is accident-plausible: a model printing the child env while debugging. The builder's stated residual ("an env copy written to a file with no print verb") understates it: the env object can reach the transcript through any alias.
Fix (replace G:692-695):
```
  has_secret_print_context "$text" "$ref" && { printf '%s' "$text"; return 0; }
  out="$(printf '%s' "$text" | sed -E \
    -e 's/(\.\.\.|\*\*)[[:space:]]*(process\.env|os\.environ)([^A-Za-z0-9_.[]|$)/\1ENV_PASSALONG\3/g' \
    -e 's/(env[[:space:]]*(:|=)[[:space:]]*)(process\.env|os\.environ)([[:space:]]*[,;})]|[[:space:]]*$)/\1ENV_PASSALONG\4/g' \
```
with
```
  has_secret_print_context "$text" "$ref" && { printf '%s' "$text"; return 0; }
  local ids id
  ids="$(printf '%s' "$text" \
    | grep -oE -- '[A-Za-z_][A-Za-z0-9_]*[[:space:]]*=[[:space:]]*(\{[^}]{0,60}|dict\()?(\.\.\.|\*\*)?[[:space:]]*(process\.env|os\.environ)' \
    | sed -E 's/[[:space:]]*=.*$//' | sort -u)"
  for id in $ids; do
    case "$id" in *[!A-Za-z0-9_]*|"") continue ;; esac
    has_secret_print_context "$text" '\<'"$id"'\>' 40 && { printf '%s' "$text"; return 0; }
  done
  out="$(printf '%s' "$text" | sed -E \
    -e 's/(\.\.\.|\*\*)[[:space:]]*(process\.env|os\.environ)([^A-Za-z0-9_.[]|$)/\1ENV_PASSALONG\3/g' \
    -e 's/((^|[^A-Za-z0-9_$.])env[[:space:]]*:[[:space:]]*)(process\.env|os\.environ)([[:space:]]*[,;})]|[[:space:]]*$)/\1ENV_PASSALONG\4/g' \
    -e 's/([(,][[:space:]]*env=)(process\.env|os\.environ)([[:space:]]*[,;})]|[[:space:]]*$)/\1ENV_PASSALONG\3/g' \
```
Predicted outcome: the three FP3 must-allow cases still pass (`childEnv` and the kwarg `env` have no print verb within 40 chars before them; the python `.replace(...)` text has no `ID = ref` assignment). `const env = process.env; console.log(env)` and the spread-alias form deny again. ### F2: MEDIUM. FP1 sourcing narrowing drops command positions main covered
G:1163-1165. The new boundary set has no JSON line-break escape (`\n`, `\r`, `\t`). It also refuses `\"` as a boundary for the dot form. This loses two shapes that main matched:
1. An indented `  . FILE` or `  source FILE` on a later line of a multi-line command, for example a `then` line that dot-sources. Main matched it because the space before the verb is a non-word character.
2. `bash -c ". FILE"`, `sh -c ". FILE; ..."` and `eval ". FILE"`.

The branch comment says the path default-deny backstops these. It does not when a carveout applies: any `--env-file=` substring makes has_allow_carveout return 0 unless a read verb sits next to the path (`.` and `source` are not read verbs). The echo-string Q exemption also blanks `echo ". FILE" | bash`. In those cases has_source_sourcing was the only gate. With `set -x` in the same command, sourcing prints every `KEY=value` to the transcript.
Fix (replace G:1163-1165):
```
  local kw='((then|do|else|elif|if|while|until|time|exec|command|builtin|eval|sudo)[[:space:]]+)*'
  printf '%s' "$1" | grep -qE -- \
    '(^|[^\\]"|[;&|({`])[[:space:]]*'"$kw"'\.[[:space:]]+[^[:space:]]|(^|\\"|[^\\]"|[;&|({`'"'"'])[[:space:]]*'"$kw"'source[[:space:]]+[^[:space:]]'
```
with
```
  local kw='((then|do|else|elif|if|while|until|time|exec|command|builtin|eval|sudo)([[:space:]]|\\[nrt])+)*'
  local ws='([[:space:]]|\\[nrt])*'
  printf '%s' "$1" | grep -qE -- \
    '(^|[^\\]"|\\[nrt]|[;&|({`])'"$ws$kw"'\.[[:space:]]+[^[:space:]]|\\"[[:space:]]*\.[[:space:]]+[^[:space:]A-Z\\]|(^|\\"|[^\\]"|\\[nrt]|[;&|({`'"'"'])'"$ws$kw"'source[[:space:]]+[^[:space:]]'
```
This makes a JSON line break a command position, which is the same convention has_env_dump and strip_safe_existence_operands already use. It also accepts a dot after an escaped quote unless the next word is capitalised: a sentence ending in a closing quote continues with a capital letter, while a dot-source operand starts with `~`, `/`, `.`, `$` or a lowercase name. It also closes main's existing gap for unindented `\n. FILE`. Predicted outcome: the FP1 cases still allow, since no line in them starts with `. ` or `source `. The builder must re-run T, because the real lane-62 report text might contain `\". ` followed by a lowercase word. Twins to add: a multi-line command `node --env-file=SAMPLE a.mjs` + `\n  . SAMPLE` must deny "sources a secret file", and `bash -c ". SAMPLE"` must deny.

### F3: MEDIUM. `.key` property stripping is not confined to property access (FP1/FP4)
G:1200-1201. Shape (1) has no left context at all, so `IDENT.key` followed by a space and `==` is blanked anywhere, including `cat /any/dir/server.key ==`: cat prints the key, and the `==` operand only produces an error. Shape (2)'s openers `[[:space:]]=`, `return`, `,`, `[` and `(` are all valid shell argv tokens or brace/extglob syntax. So `cat = server.key;`, `cat return server.key;`, `cat [ server.key ]`, `cat {/dev/null,server.key}` and, with extglob, `cat @(server.key)` are blanked as well. Main denies all of these. Reaching them takes a decoy token, so it is intent rather than accident, but this fails criterion (a). Neither FP needs any opener other than `=>` (FP1: `(n) => n.key === 'x'` and `(n) => n.key)`; FP4: `(x) => x.key)`). In shell, `=>` makes the next word a redirect *target*, so the name is written to, never read.
Fix (replace G:1200-1201):
```
    -e 's/([A-Za-z_$][A-Za-z0-9_$]*(\.[A-Za-z_$][A-Za-z0-9_$]*)*)\.key([[:space:]]*(===|!==|==|!=))/\1.KEYPROP\3/g' \
    -e 's/(=>|[(,[]|&&|\|\||\.\.\.|[[:space:]]=|return)([[:space:]]*)([A-Za-z_$][A-Za-z0-9_$]*(\.[A-Za-z_$][A-Za-z0-9_$]*)*)\.key([[:space:]]*[]),};])/\1\2\3.KEYPROP\5/g' \
```
with
```
    -e 's/(=>[[:space:]]*)([A-Za-z_$][A-Za-z0-9_$]*(\.[A-Za-z_$][A-Za-z0-9_$]*)*)\.key([[:space:]]*(===|!==|==|!=))/\1\2.KEYPROP\4/g' \
    -e 's/(=>)([[:space:]]*)([A-Za-z_$][A-Za-z0-9_$]*(\.[A-Za-z_$][A-Za-z0-9_$]*)*)\.key([[:space:]]*[]),};])/\1\2\3.KEYPROP\5/g' \
```

Also update the function comment at G:1176-1191. Predicted outcome: the FP1 heredoc, the FP1 one-liner and FP4 still allow, and the six existing key twins still deny. ### F4: MEDIUM. Moving the substitution bailout after blanking lets `$(...)` hide inside a fake heredoc in a double-quoted string (FP2)
G:1347-1348 together with G:1357. The awk exempt-receiver test accepts `"` as a command boundary, and that includes the JSON-escaped *shell* quote `\"`. Take `echo "cat > f <<'EOF'` + newline + `$(cat SECRET)` + newline + `EOF"`. awk marks a cat>file heredoc, blanks the next line, and never sees its delimiter, because that line is `EOF\"`. The `$(...)` has disappeared before the bailout runs, so the branch allows the command. Bash, however, expands the `$(...)` inside the outer double quotes, and echo prints the file to the transcript. Main bailed on the `$(` and denied. The same fake heredoc followed by a trailing `; cat SECRET` (no substitution) is already allowed on main (pre-existing, P1 below). This change adds a second shape through the same hole, and one patch closes both.
Fix (G:1347-1348): require an unescaped quote:
```
        is_cat = (combined ~ /(^|["`;&|(])[ \t]*cat([ \t]+[^|;&]*)?>>?[ \t]*[^ \t|;&]+/)
        is_tee = (combined ~ /(^|["`;&|(])[ \t]*tee([ \t]+-[A-Za-z-]+)*[ \t]+[^ \t|;&-][^ \t|;&]*/)
```
with
```
        is_cat = (combined ~ /(^|[^\\]"|[`;&|(])[ \t]*cat([ \t]+[^|;&]*)?>>?[ \t]*[^ \t|;&]+/)
        is_tee = (combined ~ /(^|[^\\]"|[`;&|(])[ \t]*tee([ \t]+-[A-Za-z-]+)*[ \t]+[^ \t|;&-][^ \t|;&]*/)
```
Predicted outcome: a heredoc opened at the JSON string start or after `;`, `&`, `|`, `(` or a backtick is still exempt, so the FP2/FP4 cases pass. A heredoc inside a shell double-quoted string (`echo "..."`, `ssh h "cat > f <<'EOF'..."`) is scanned in full again, which is main's behaviour. Twin to add: `echo "cat > f <<'EOF'\n$(cat SAMPLE)\nEOF"` must deny.
