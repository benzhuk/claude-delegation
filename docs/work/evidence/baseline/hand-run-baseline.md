# Hand-run build baseline (builds before 2026-09-20)

Method. Five builds were picked from the ten on the lane-61 candidate list, favoring a clear ask, a clear acceptance, different projects and both reachable hosts, and real multi-file changes. Multi-file was checked from the transcripts' own edit and commit tool calls and, for the Windows builds, from the repo's commit stats. Each cited line was re-read in the lead transcript (jsonl line numbers, 1-based) with a small read-only line viewer that shows only a window of lines. Times are America/New_York. The ask is the first user turn that states the build. The acceptance is the turn where the owner told the lead to ship or accepted the result. Hours are acceptance time minus ask time. Rework counts owner turns after the acceptance that redo or fix the same build's output. The candidate list points to no later session, so only the same session was searched. Lost/stalled counts, inside the ask-to-accept window: silent gaps over 2 h between consecutive transcript events, usage-limit stalls over 2 h, subagents that died and were relaunched, and reports that never arrived. Tokens are the build-census top-tier (lead-model family) figure copied unchanged from the candidate list. Two caveats apply. First, the census windows for builds 2 and 3 also cover unrelated work running in the same session, so their tokens overstate the build. Second, build 2's census window starts 29 s after the ask line used here (it starts at line 35, a fuller restatement of the line-13 ask).
