### R3-6 MEDIUM, integrity: the not-on-main refusal sits after the run has already changed the checkout

Evidence: `executable_dotfiles-sync.sh:230-231`. The builder's report says that off main "the capture phase fails, so the run exits nonzero, alerts, and apply is skipped". On Netcup that holds only when the live env file exists and the branch is not behind:

- 7f: on a feature branch that is ahead of origin/main and behind it, `phase_pull` (line 207) runs `git rebase origin/main` on the feature branch before the refusal. The branch's commits are rewritten every 30 minutes. A branch already pushed to its own remote branch then diverges, and the next plain push is rejected, which invites a force push. This is the round-0 setup (the chezmoi checkout on the bet branch).
- 7e: with the live env file absent, `phase_capture` returns 0 at line 285 without calling `push_if_ahead`. `phase_apply` then runs `chezmoi apply --force` from the feature branch's tree. That deploys an unreviewed tree to a live host, which is the harm M288 names, and the run exits 0.
