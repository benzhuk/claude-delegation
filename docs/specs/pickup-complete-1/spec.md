## Territory P1: skills/decisions/scripts/decisions-pickup.mjs, decisions-pickup.test.mjs, registered-pickup.contract.test.mjs
1. Option (b). The active-round change check compares the owner-input digest (contracts.md C1), not raw bytes. A checked page whose bytes differ but whose owner inputs are identical to the round's capture is not a change: the receipt stays in its state (a RECORDED round stays RECORDED) and the pass reports its existing state. A difference in owner inputs keeps today's NEEDS_RECONCILIATION path unchanged.
2. A round already moved to NEEDS_RECONCILIATION by the old byte check (reason exactly "checked page bytes changed during the active round", previousState RECORDED) whose reconciliation capture has owner inputs equal to the round's original capture may be accounted by `account`, exactly as a RECORDED round. The account result and the receipt say it was accounted from that state. Every other NEEDS_RECONCILIATION stays refused.
3. isMainModule canonicalizes both sides through realpath, the same way decisions-handback.mjs:390-399 does (lower-case only on win32).
4. Registration entries accept one optional key `topic` (contracts.md C3). Missing is valid. An invalid topic invalidates the whole registration, like every other entry field.
5. Tests for each. Fixtures: a page that differs only in a Closed bullet and a cleared Done line, with the same ticked option (stays RECORDED), a page with a new comment (NEEDS_RECONCILIATION), the stuck-round shape accounted, a stuck round with different inputs refused, the CLI through a symlink printing its normal output.
