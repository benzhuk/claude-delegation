# Lead rulings, pickup-complete-1 (these win over spec.md where they differ)

## C1 Owner inputs, and what counts as a change (P1)
- `export function ownerInputs(items)` in decisions-pickup.mjs maps `capturedItems(doc)` output to `[kind, title, text]` triples. `line` is dropped, because line numbers move with any edit.
- A fresh checked read is a CHANGE against the active round only when it holds an owner input the round's capture does not, compared as a multiset of triples. A new comment, a new tick, or an altered text are changes. Inputs that disappear are the lead acting on them, not the owner adding anything, so a fresh read whose inputs are a sub-multiset of the capture is not a change. Raw-byte differences alone are never a change.
- Not a change: the receipt file is not rewritten, no reconciliation capture is written, and the pass returns `receiptStatus` of the existing receipt. A change keeps today's `changedReceipt` path byte for byte.
- The same rule applies at the CAPTURE_INTENT branch (:924-940) only where it calls `changedReceipt`. The other CAPTURE_INTENT refusals are unchanged.
- The stuck-round account (spec P1.2): `account` accepts state NEEDS_RECONCILIATION only when `reconciliationReason === 'checked page bytes changed during the active round'`, `previousState === 'RECORDED'`, and the reconciliation capture (`reconciliationPrivateCaptureRef`, opened through the existing validating capture reader) has owner inputs that are a sub-multiset of the round's original capture. The accounted receipt keeps every existing field and adds `accountedFrom: 'NEEDS_RECONCILIATION'`. Everything else `account` checks (outcome report, Accounted-ref for every capture ref of the ORIGINAL capture) is unchanged.

## C2 Title format (P3)
`<Topic>: <M>/<D> <h>:<mm><AM|PM> Decisions`, with the time in America/New_York via Intl (never a fixed offset). M, D and h have no leading zero, mm is two digits, and h is 12-hour (00:05 -> 12:05AM, 12:00 -> 12:00PM). One space after the colon and one before "Decisions". Parse regex, anchored: `^(.+): (\d{1,2})\/(\d{1,2}) (\d{1,2}):(\d{2})(AM|PM) Decisions$`. Exported: `formatTitle(topic, date)`, `parseTitle(title)` -> `{topic, month, day, hour24, minute}` or null.

## C3 Topic (P1 validates, P3 reads)
- Registration entry optional key `topic`: a string matching `^[A-Za-z][A-Za-z0-9 &._-]{0,39}$` (no colon). P1's `exactKeys` accepts the five keys, or the five plus `topic`. A registration with an invalid topic is invalid as a whole.
- `decisions-title.mjs set` resolves the topic in this order: `--topic`, then the registration entry for the same page (`$AGENTS_HOME/ws/decisions-pickup/registrations.json`, where AGENTS_HOME defaults to `~/.agents`. Read-only. A missing or unparsable file is skipped, never fatal, never written), then the topic parsed from the page's current title if it matches C2. With no topic from any of these it exits 2. The flag is validated with the same regex.

## C4 Historical headings (P2)
A top-level page H1 (the same test decisions-read.mjs already uses for `Closed`, reading the title with its trailing `{toggle="true"}`-style attribute stripped as today) is historical when the title matches `^(?:First )?[Bb]earings\b`. Inside it the Closed-scope rules apply unchanged: `archivedTitles`, comments and checkbox options still live. `# Closed` behaviour is byte-identical. Live headings to use as fixtures: `# Bearings — September 26, 2026 (independent, Opus) {toggle="true"}`, `# Bearings — September 27, 2026`, `# First bearings assessment — September 23, 2026 {toggle="true"}`.

## C5 decisions-title.mjs CLI and API, and the hand-back check (P3)
- `node decisions-title.mjs set --page <32-hex or dashed> [--topic <T>] [--now <ISO>]` sends one `PATCH https://api.notion.com/v1/pages/<id>` with body `{"properties":{"title":{"title":[{"type":"text","text":{"content":"<title>"}}]}}}` and prints `TITLE <new title>`. A GET is sent first only when the topic must come from the current title.
- `node decisions-title.mjs meta --page <id>` sends one GET and prints JSON `{"page":"<32-hex>","title":"<plain text of the title-type property, empty if none>","last_edited_time":"<API value>"}`.
- Headers: `Authorization: Bearer <NOTION_TOKEN from the environment>` and `Notion-Version` equal to the constant ~/.claude/scripts/notion.js uses for `/pages` (copy the value, do not import notion.js). 20 s timeout. Exits: 0 ok, 2 usage or no topic, 3 NOTION_TOKEN unset (the message names the variable, never a value), 4 HTTP or network error (the message gives the status and the Notion error code only). `fetch` is injectable through the exported `run({argv, env, fetch, now, stdout, stderr})`, and isMainModule uses realpath as in decisions-handback.mjs.
- decisions-handback.mjs `--title-meta <file>`: JSON as printed by `meta`. When the repo config has `decisions_url`, `page` must equal it. The title must parse by C2. Title time: the NY wall time in the year of last_edited_time's NY date, minus one year when that lands more than one day after last_edited_time. It is STALE when last_edited_time is more than 2 minutes after the title time. The retitle itself moves last_edited_time, and Notion rounds it to the minute. Output lines: `title ok: <title>`, `TITLE off-pattern: <title>`, `TITLE stale: <title> vs last edit <ISO>`, and `TITLE unchecked: run decisions-title.mjs meta --page <id> and pass --title-meta`. Any line but `title ok` blocks `HANDBACK ok` with exit 1. An unreadable or malformed meta file is exit 3, like an unreadable page.

## Attack brief for every reviewer
- P1: a fresh read that removes one ticked option and adds a different one (a change: the multiset test, not a count). Two comments with the same text where the fresh read has three. A title renamed by the lead while an input sits under it: the title is part of the triple, so a rename is a change. Rule whether that is right and say so. A receipt in UNKNOWN that the new account path must not accept. The symlink CLI on a path whose case differs on Linux. A topic of 41 chars, a topic with a colon, a registration with `topic: null`.
- P2: `# Bearingsless`, and `# bearings` in lower case (matches by the regex: is that fine?). An H1 inside a toggle's indented content (must not open scope). An owner comment and a ticked box inside a Bearings section (still reported). The `# Closed` fixtures byte-identical in output.
- P3: 11:59:59 -> 12:00 across the PATCH, midnight on New Year's Eve, a DST fall-back hour (1:30AM twice). A title with extra spaces. A topic from a registration for a different page. A meta file for a different page. A token in any output. A check that passes because it isn't looking: a handback test that never feeds a stale title, or a meta whose last_edited_time is unparsable being treated as fresh.
