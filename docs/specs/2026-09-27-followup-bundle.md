## Lane 22, windows-task: the janitor timer registers on Windows

Lead: skills-o (Windows; the proof is live on this machine). Territory: `scripts/install-janitor-timer.mjs`, `scripts/install-janitor-timer.test.mjs`, the doc the script's header names as its own.

Defect: on 2026-09-27 `install-janitor-timer.mjs --enable` on Windows wrote the task XML as UTF-8 with a UTF-8 declaration and `schtasks /Create /XML` refused it: "The task XML is malformed. (1,40) unable to switch the encoding". Task Scheduler's XML import requires UTF-16. The comment at install-janitor-timer.mjs:274-276 chose UTF-8 so that `readMarked`'s utf8 marker check would keep working; that is the one wrong choice, and the rest of the XML (WorkingDirectory, StartWhenAvailable, IgnoreNew, the cmd log redirect to last-run.log, :280-297) is right and must stay.

Pinned design: the `.task.xml` is written as UTF-16LE with a BOM and declares `encoding="UTF-16"`; `readMarked` decodes a `.xml` file that starts with the UTF-16LE BOM as UTF-16 before the marker check, so ownership, the foreign-file check (tests at :330 and :513) and the file layout are unchanged. Everything else about the Windows path stays exactly as today: without `--enable` the files and installed.json are written and nothing is shelled out (header :32-33, test :549-561); `--remove` deletes only marked files and, with `--enable`, runs `schtasks /Delete /TN <name> /F`. The `.task.xml` that 0.20.15 left on this box is at the same path and is overwritten by the next install. Tests at :549-569 (the UTF-8 declaration assertions) are rewritten for UTF-16. Fallback only if the UTF-16 file is still refused live: `schtasks /Create /SC ... /TR ...` with the 261-character `/TR` limit checked in code and a stated loss of WorkingDirectory and StartWhenAvailable; the record must say why the fallback was taken.

Acceptance: (a) unit tests: BOM present, declaration says UTF-16, `readMarked` recognises the marker in a UTF-16 file and still refuses a foreign file, the no-enable path writes and does not shell out; (b) LIVE on Windows, in the record: `install-janitor-timer.mjs --enable --json --repo <ref checkout>` exit 0, `schtasks /Query /TN janitor-record /FO LIST` showing Next Run Time, `wiring-check.mjs --json` janitor line, then `--remove --enable --json` and the Query saying the task cannot be found, then a final `--enable` left in place (Ben approved the janitor timer on all four hosts on 2026-09-27, 12:38 PM NY). The collect-status job is NOT wired on Windows in this lane (the collector runs on Netcup only); say so in the record. (c) sealed suite green on Netcup or Hetzner from origin (systemd path untouched).

## Lane 23, record-closed-and-skip: a closed status the tooling can name, and no noise rows

Pinned design: (1) `STATUSES` gains `closed` after `accepted`. `work-record.mjs close --record <path> --merge <sha> --at <ISO> [--repo <dir>] [--main <ref>]` is the only way in: it refuses unless Status is `accepted`, unless `--merge` is an ancestor of `--main` (default `origin/main`, one `git merge-base --is-ancestor` in `--repo`, no fetch), and reuses accept's clock bound on `--at` (commit 5d8eccf); it appends a Log line `closed <ISO> merge <sha>`. `closed` is terminal: `withdraw` refuses it and no command transitions out. `validateRecord` applies every accepted-status check (work-record.mjs:213-240) to `closed` plus the presence of the `closed` Log line, so a hand-edited `Status: closed` without them fails. `continuation.mjs` derives its buckets from `STATUSES` (this also fixes the existing `withdrawn` throw); test: a snapshot over records in every status, including closed and withdrawn, never reports SELECTION_UNREADABLE. The collector does not gain a `closed` state: a closed lane's branch is an ancestor of main and drops out of collect-from-origin's listing (:4-6); the record's close commit lands on main after the merge, per the Closed-entry flow. (2) `collect-from-origin.mjs` and `collect-status.mjs` gain `--only-prefix <p>` (repeatable). `collect-status.mjs` has `DEFAULT_ONLY_PREFIXES = ["build/"]` applied when no `--only-prefix` is given (lanes are `build/<lane>-1` by this spec's own rule); `--only-prefix ""` disables the default and lists everything. Branches outside the prefixes are counted in one status.md line `skipped: n (outside build/)` and never listed as rows. The change key is computed over listed rows only; the first run after upgrade therefore sends one RESULT, and that RESULT is real and expected (say so in the record and in the collect doc). (3) The derived-state column is renamed `lane` in status.md, with a one-line legend under the table header saying every non-terminal Status shows as `owned`; JSON keeps the field name `state`. Test: identical listed rows produce an identical change key before and after the rename.

Acceptance: unit tests for close (refusals: not accepted, not an ancestor, already closed, clock bound; success appends the Log line), for validateRecord on closed, for continuation buckets, for prefixes (default on, disabled, explicit, skipped count line), for the legend line and change-key stability; the lane's own record is closed with the new command as the live proof; sealed suite green on a second host.

## Lane 24, sealed-home-leak: the sealed test home never outlives its suite

Lead: skills-n (Netcup, where 585 leaked directories filled inodes to 70 percent before Ben approved their deletion on 2026-09-27, 10:46 AM NY). Territory: `scripts/test-home.mjs`, `scripts/test-home.test.mjs`, `scripts/run-tests.mjs`, `scripts/run-tests.test.mjs` if it exists.

Defect: `test-home.mjs:52` creates `sealed-home-*` under the OS temp dir; `run-tests.mjs:101-106` cleans up in a `finally` that keeps a FAILED suite's home on purpose (RT-18/F6) and never runs when the suite is killed (SIGINT, SIGTERM, a pane closed, an ssh session dropped).

Pinned design: (1) `makeTempHome` registers its directory in a per-process list and installs, once per process, one handler each for `exit`, `SIGINT`, `SIGTERM` and (off win32) `SIGHUP` that removes every still-registered directory synchronously and then re-raises: remove its own listeners, then `process.kill(process.pid, signal)`, giving exit code 128+n on POSIX. `makeTempHome` returns a `keep()` (alias `unregister()`) that removes the directory from the list; `run-tests.mjs` calls it on a non-zero suite result so the keep-on-failure behaviour is unchanged. (2) `run-tests.mjs` sweeps, at start, every `sealed-home-*` directly under the temp dir whose mtime is older than 6 hours, prints one line `swept n stale sealed homes`, and skips the sweep when `~/.agents/ws-off-sweep` or the shared `~/.agents/ws-off` exists (kill switch; a sweep error is printed and the suite runs anyway). Never anything younger than 6 hours (another suite on this host may own it), never a name that does not match the exact prefix. `--no-sweep` for the sweep's own tests. On win32 the sweep is the guarantee: `child.kill('SIGTERM')` terminates a Windows process without running handlers, so the signal test is skipped there with that reason stated in the test.

Acceptance: unit tests: a child node process that makes a temp home and is killed with SIGTERM leaves no directory (POSIX only, skipped on win32 with reason); a failing suite keeps its home; a passing suite removes it; the sweep removes old, keeps young, keeps non-matching, honours both kill switches; registration is idempotent (one listener per event after two homes). Live proof on Netcup in the record: `ls -d /tmp/sealed-home* 2>/dev/null | wc -l` before and after one suite run. Sealed suite green on a second host.
