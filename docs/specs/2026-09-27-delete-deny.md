# Lane sixteen: a recursive delete from an agent is refused, not prompted

Written by skills-fable, 2026-09-27 02:20 New York. Spec-session: 9c61c35a-82dd-4aef-8eca-c99bb0e72e31. Spec-from: 2026-09-27T06:10:00Z. For the Claude lane lead on Windows (skills-o). Base: origin/main at pickup, one sha (806d773 or later). Branch build/delete-deny-1. Builders in their own worktrees.

## Why
Twice tonight a mid-tier builder chained `rm -rf` into a command although its mandate carried the sentence forbidding it, and sat on the permission prompt that nobody watches: 3.5 hours in lane ten (2026-09-26 18:44), 40 minutes in lane fifteen (2026-09-27 01:02). Lane thirteen added the sentence to agents/builder.md and to the build-loop role rules; lane fifteen's builder had it in its mandate and did it anyway. A text rule has now failed under measurement twice, which by this project's own standard means it is replaced by a mechanical one. The permission layer does not catch it either: `~/.claude/settings.json` denies the tool pattern `Bash(rm -rf *)`, which matches only a command that begins with those bytes, so `git clone … && rm -rf …` falls through to the classifier and to the prompt. A PreToolUse hook that denies returns to the agent at once with a reason, and the agent adapts; the plugin already has one PreToolUse hook (hooks/agent-dispatch-guard.mjs) with the kill switch, observe mode and fail-open shape to copy, and an Agent or SendMessage matcher only. Nothing matches Bash or PowerShell.

Measures: work lost or stalled (4 lane-hours in one night, and every hang of this kind from now on becomes a 2-second refusal). Must not worsen: top-tier tokens per build (no new turn; the refusal reaches the builder that made the call), hours ask to accepted (a builder that needed a delete asks the lead in its report, which is what the rules already say).

## Territory D1: hooks/delete-guard.mjs, hooks/delete-guard.test.mjs, hooks/hooks.json, docs/sealed-tests.md (one sentence), agents/builder.md (one sentence)
1. A PreToolUse hook registered in hooks/hooks.json with matcher `Bash|PowerShell`, command shape identical to the dispatch guard's entry. The script reads the hook JSON from stdin; on any parse failure, missing field or thrown error it prints nothing and exits 0 (fail open), exactly as agent-dispatch-guard.mjs does at its top and bottom.
2. Kill switches: `~/.agents/no-delete-guard` (this hook only) and the shared `~/.agents/ws-off`; either present means print nothing, exit 0. Unlike the dispatch guard, this one enforces by default: the failure it fixes is unattended, so an opt-in enforce file would leave it off exactly where it matters. Say so in the file header.
3. Matching is a pure function `decide(input)` over `tool_input.command` as one string, case-insensitive where the shell is, anywhere in the string (compound commands are the case that bit): `rm` with any flag group containing `r` or `R` or the word `--recursive`; `rmdir /s` and `rd /s`; `Remove-Item`, `ri`, `del`, `erase` with `-Recurse` or a `-r` abbreviation; `git clean` with `-f`, `-d` or `-x` in any flag group; `git worktree remove --force` and `git worktree prune`; `find … -delete`; `Remove-Item … -Force` on a directory path is not distinguishable by regex and is out of scope, say so. Two allowances, pinned by tests: `git worktree remove <path>` without `--force`, and `git branch -d` and `-D` (the janitor's sanctioned verbs, scripts/janitor.mjs; branch deletion is not a directory delete). A match inside a quoted string that is an argument to `grep`, `echo`, `printf`, `git commit -m` or `note-send --text` is not a delete; handle the simple cases (the verb appears only inside single or double quotes following one of those words) and let the reviewer attack the rest. False refusals are cheap (the agent rephrases or asks); false passes cost hours, so when in doubt refuse.
4. The builder confirms in the record's Log, from a real subagent run of `echo`, that `agent_id` is present on a subagent's Bash call and absent on the lead's; if it turns out absent on subagent Bash calls, the rule becomes deny for every caller and the record says so with the evidence. Do not guess this; run it.
5. The deny is the JSON the dispatch guard emits (`hookSpecificOutput.permissionDecision: "deny"` with `permissionDecisionReason`), reason text: "delete-guard: recursive delete refused for an agent (<matched verb>). Removal of worktrees and scratch is the lead's own standalone command; report what needs deleting. Kill switch ~/.agents/no-delete-guard." One log line per matched command to `~/.agents/notes/delete-guard.log` in the existing `<stamp> <verb> …` shape, verbs `denied` and `passed-lead`; a command that matches nothing is not logged. Never log the whole command; log the matched verb and the first 80 characters.
