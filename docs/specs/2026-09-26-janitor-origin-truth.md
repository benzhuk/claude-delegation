## Why
On Netcup after lane eight, the janitor's first `--apply` left three merged branches standing. skills-n traced it: `scripts/janitor.mjs` calls a branch merged when it is an ancestor of local `refs/heads/main` (janitor.mjs, `isBranchMerged`), and that checkout's main was six releases stale; the origin check is only a second confirmation, and the script never fetches, so "as of last fetch" can be days old. Deletion uses `git branch -d`, which git judges against the checkout's HEAD or the branch's upstream, so even a branch proven merged on origin is refused in a stale checkout. Lane five kept both behaviours (it added the first-parent UNSTARTED guard, which does prefer origin/main, and a report-only remote class). The record of truth for this repo is origin: lanes merge on origin, the collector reads origin, the four-number read reads origin. The janitor is the one tool still asking the local checkout.

Measures: work lost or stalled (stale worktrees and branches survive cleanups and keep confusing leads), top-tier tokens per build (no lead re-runs a cleanup by hand). Must not worsen: rework after acceptance (nothing not proven merged on origin may be deleted; that safety gets stricter, not looser).

## Territory J1: scripts/janitor.mjs, its tests, skills/janitor/SKILL.md
1. Fetch first. Every run that will judge merges begins with `git fetch origin --prune` in the root; a failed fetch (offline, no remote) downgrades every merge judgment to UNVERIFIABLE, never to SAFE, and the report says so on its first lines. `--no-fetch` skips it and the report then labels every verdict "as of last fetch, <age>" from the origin ref's reflog or FETCH_HEAD mtime.
2. Merged means an ancestor of `refs/remotes/origin/<main>`. Local main plays no part in SAFE; a branch merged only into local main is JUDGMENT with the existing wording. Keep the first-parent UNSTARTED guard exactly as lane five shipped it.
3. Deleting a branch that is proven merged on origin uses `git branch -D` (the ancestry check above is the safety, not git's `-d` heuristic, which reads the checkout's HEAD). `-D` is only reached from the SAFE class after the origin ancestry check passed in this same run, after the fetch; anywhere else in the script deletion stays as it is. One test pins that a branch merged on origin but not in local main is deleted under `--apply`, and one pins that a branch merged only locally is never deleted.
4. Worktrees: same rule; a worktree whose branch is merged on origin is SAFE; remove uses the existing `worktree remove --`.
5. SKILL.md: replace whatever describes the merged test with the origin rule and the fetch, in the existing voice; no new sections.
6. Tests: fixture with a bare origin, a stale local main, and the three cases (merged on origin only, merged locally only, merged on both); the fetch-failure downgrade; `--no-fetch` labelling. Existing tests stay green or are updated only where they asserted local-main semantics, and each such change is named in the record's Log.
