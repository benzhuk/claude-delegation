## 1. Host table and sender-host resolution (contracts R1)

One frozen constant `{ name, addr, user, os }` for the four hosts. `--sender-host <name>` looks up
by name (case-sensitive to the table's own names is fine; validate against it — unknown name is a
usage error, exit 1, distinct from "unknown address"). Otherwise read `SSH_CONNECTION`'s first
whitespace-separated field, or if absent `SSH_CLIENT`'s first field, and look up by `addr`.
Nothing else is read. When the mapped host's `name` equals `os.hostname()`'s first label
(case-insensitive, split on `.`), there is no mirror and `mirrorLedger` is absent from the result
entirely (not `ok:true`, not `ok:false` — absent, per R1's exact wording). An unmapped address (no
`--sender-host`, and the SSH env address matches no row) means no mirror, and `mirrorLedger:
{host: null, ok: false, error: 'unknown-sender-address'}`. No `SSH_CONNECTION`/`SSH_CLIENT` and no
`--sender-host` at all: local, nothing changes, no `mirrorLedger` key (this is almost every plain
local run — make sure it stays silent, not a false "unknown-sender-address").

## 2. `--append-ledger` mode (contracts R2)

New mode: `note-send --append-ledger <YYYY-MM-DD>`. Reads exactly one line from stdin (at most 700
chars plus the newline — reuse `MAX_LINE` from envelope.mjs, reject over-length before parsing).
Refuses (exit non-zero, nothing written) unless the line parses with `parseEnvelope` (envelope.mjs)
AND the date arg matches `^\d{4}-\d{2}-\d{2}$`. On success, append the line + `\n` to
`notesMirrorPath(os.homedir(), day)` using the same `appendLine` helper the normal ledger write
uses (same encoding, no BOM). Does nothing else — no delivery, no outbox, no repo ledger write, no
mirror of its own. That is the "never re-mirrored" guarantee by construction (spec item 3) — pin it
with a test that runs `--append-ledger` and asserts no mirror dependency is ever invoked and no
outbox entry is written.

## 3. The mirror call itself (contracts R2, R3)

After the local ledger write succeeds (the `for (const t of ledgerTargets) appendLine(...)` loop,
per the scout's line reference), if the sender host resolves to a REMOTE mapped host: spawn
`ssh -o BatchMode=yes -o ConnectTimeout=3 <user>@<addr> <remote>`, where `<remote>` is
`~/.local/bin/note-send --append-ledger <day>` for Linux/macOS and `note-send --append-ledger
<day>` for Windows, with the envelope line on stdin. `<day>` is the same day key (`ymd`) this
send's own local ledger write used. Hard 5 s timeout: kill the child, report
`mirrorLedger: {host, ok: false, error: 'timeout'}`. No retry, ever. On a non-zero exit or spawn
error: `ok: false` with a short error — exit code and the first stderr line truncated to 120 chars,
never the note's own text (version skew with an old peer note-send that rejects the unknown flag
must degrade to exactly this shape, not throw). On success: `mirrorLedger: {host, ok: true}`. The
ssh spawn is an injected dependency (`deps.spawnMirror(cmd, args, {input, timeoutMs}) ->
{ok, code, stderr}` or an equivalent shape you choose) — tests never run a real ssh. No special
case for `--to ben` or any kind — it mirrors like any other send (contracts R3 says the reviewer
may challenge this; don't pre-empt the challenge by adding a carve-out).

`--dry-run` (which returns before the ledger write, per the scout's note on :488-515) reports the
planned mirror — host name and the exact remote command string — without spawning anything, added
to the existing `plan` array. `--no-mirror` skips the mirror unconditionally, whatever the sender
host resolves to, and is silent about it (no `mirrorLedger` key at all, same as the local case) —
add it to `BOOL_FLAGS` alongside `--sender-host` in `STRING_FLAGS`.
