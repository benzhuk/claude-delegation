# Lane fifteen: a remote send leaves its line on both hosts

Written by skills-fable, 2026-09-27 00:05 New York. Spec-session: 9c61c35a-82dd-4aef-8eca-c99bb0e72e31. For the Claude lane lead on Netcup, after lane thirteen merges. Base: origin/main at pickup, one sha. Branch build/ledger-both-halves-1. Builders in their own worktrees.

## Why
A note to a peer on another machine is sent by running note-send on that machine over ssh, so the envelope line lands in the recipient host's ledger and nowhere else. Every cross-host conversation is therefore split: Netcup holds the ASKs from Windows, Windows holds the RESULTs from Netcup. Lane thirteen's Opus review found the consequence first: an overdue-ASK pass on either host sees half the thread and cannot tell an answered ASK from a stalled one, so lane thirteen ships with a rule that nudges only when the answer side is observable on that host, and logs `overdue-cross-host` otherwise. skills-n's lane ten findings show the same split elsewhere: the four-number read on Netcup listed a Windows-recorded ACK as unanswered. Every reader of a host ledger is wrong by half for cross-host pairs.

The smallest fix is at the source: when note-send runs on a host other than the sender's, the same envelope line also lands in the sender's host ledger. Then both hosts hold both halves, lane thirteen's rule turns on for cross-host pairs by itself, and the four-number read sees its ACKs.

Measures: work lost or stalled (the overdue pass covers tonight's exact case, a cross-host stall), rework after acceptance (the census stops misreading cross-host ACKs). Must not worsen: top-tier tokens per build (no new turn for anyone; one extra append per remote send).

## Territory L1: skills/multi/scripts/note-send.mjs, its test, skills/multi/SKILL.md, references/envelope.md if a field is added
1. Sender host, in one place: note-send learns the sender's host from an explicit `--sender-host <hostname>` when given, else from the `SSH_CONNECTION`/`SSH_CLIENT` environment (the client address, mapped to a host name through the tailnet address table already written in the multi skill: Windows ben-desktop, Netcup 100.69.249.18, Hetzner 100.111.119.54, Mac 100.116.13.27), else it is local and nothing changes. Do not read any environment variable other than those two; never print their values.
2. When the sender host is another machine: after the local ledger write succeeds, append the identical envelope line to that machine's `~/.agents/notes/<today>.md` over ssh in one short command (`ssh <user>@<addr> 'cat >> ~/.agents/notes/<day>.md'` with the line on stdin, or the equivalent that keeps the line inert), with a bounded timeout (5 s) and no retry. Failure is logged in the JSON result as `mirrorLedger: {host, ok: false, error}` and never changes the exit code or the delivery outcome; the local write is the fact, the mirror is best effort. The repo ledger (`docs/ledger`) is not mirrored in this lane; say so in the docs.
3. The mirrored line is byte-identical to the original, including its id, so dedup by id keeps working; nothing about the line says it is a mirror. A mirrored line must never be re-mirrored (the append is a raw file write, not a note-send, so this holds by construction; pin it with a test anyway).
4. `--dry-run` prints the planned mirror append without doing it. `--no-mirror` skips it.
5. Tests with the existing note-send fixtures: sender host given explicitly (mirror planned), ssh environment present with a known address (mirror planned to the mapped host), unknown address (no mirror, logged), local (no mirror), mirror failure leaves exit code and delivery unchanged, dry-run shows the command, the byte-identical line. The ssh call is injected as a dependency in tests and never run.
6. SKILL.md: the cross-host paragraph gains two sentences: the line now lands on both hosts, and what `mirrorLedger` in the result means. The lane thirteen paragraph's `overdue-cross-host` sentence gains "until the sender's host has the thread too, which the mirror now gives it".
