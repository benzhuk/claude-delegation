## What was built

**Host table / sender-host resolution (contract R1)** — `MIRROR_HOSTS` (frozen, 4 rows, exact
addr/user/os from contracts.md Facts) and `resolveSenderHost(args, env, hostTable)` in
`note-send.mjs`. `--sender-host <name>` looks up by name (unknown name → `NoteError(1)`, distinct from
an unmapped address); otherwise `SSH_CONNECTION`'s first field, else `SSH_CLIENT`'s, looked up by addr.
No other env var is read; neither raw value is ever put in a result, log, or thrown message — only the
mapped `name`. When the mapped host's `name` equals `os.hostname()`'s first label (case-insensitive,
via `deps.hostname` for tests), `mirrorLedger` is absent entirely, not `ok:false`. A genuinely unmapped
address (SSH env present, no `--sender-host`, no table match) yields
`mirrorLedger: {host: null, ok: false, error: 'unknown-sender-address'}`. No SSH env and no
`--sender-host` at all: `mirrorLedger` key absent, silently — verified by a dedicated test.

**`--append-ledger <YYYY-MM-DD>` (contract R2)** — `runAppendLedgerMode`, dispatched at the very top of
`runNoteSend` before any `--from/--to/--kind/...` validation, since this mode needs none of it. Rejects
stdin over `MAX_LINE + 1` bytes *before* parsing (reused `MAX_LINE` from envelope.mjs, not
redefined), requires exactly one line, requires it to parse via `parseEnvelope` and the day to match
`^\d{4}-\d{2}-\d{2}$`, then appends via the same `appendLine`/`notesMirrorPath` the normal ledger write
uses. Does nothing else: no delivery, no outbox entry, no repo ledger write, and — by construction, since
this function never calls the mirror at all — no mirror of its own. Verified live end-to-end as a real
child process (not just injected deps):
```
$ HOME=$SCRATCH node skills/multi/scripts/note-send.mjs --append-ledger 2026-09-27 <<< '...'
mirrored line appended to $SCRATCH/.agents/notes/2026-09-27.md
exit=0
```

**The mirror call (contracts R2/R3)** — `runMirror(host, day, envelope, deps)`, called once per
invocation, right after `for (const t of ledgerTargets) appendLine(...)` (note-send.mjs line ~721),
before `base` is built — so it reaches every return path past that point (`isBen`, quiet-kind,
inbox-delivered, paneError, `--no-type`, permission-deferred, two-phase-delivered) because all of them
spread `base`, exactly as the scout noted. Spawns
`ssh -o BatchMode=yes -o ConnectTimeout=3 <user>@<addr> <remote>` via the injected
`deps.spawnMirror(cmd, args, {input, timeoutMs}) -> {ok, code, stderr, timedOut}` (never a real ssh in
tests; a real `spawn`-based default exists for production use but is intentionally untested here,
matching "no live ssh" in Un-agent-able steps). `<remote>` is `~/.local/bin/note-send --append-ledger
<day>` for Linux/macOS, `note-send --append-ledger <day>` for Windows (`remoteAppendCommand`). Hard 5 s
timeout → `{host, ok:false, error:'timeout'}`, no retry. Non-zero exit/spawn error → `{host, ok:false,
error}` where error is `exit <code>: <first stderr line, ≤120 chars>`, never the note's own text (a
version-skew old peer rejecting the flag degrades to exactly this). `<day>` is the same `ymd` this
send's own local ledger write used. `--dry-run` plans it (host name + exact ssh command string) in the
existing `plan` array without spawning; `--no-mirror` (new `BOOL_FLAGS` entry, alongside `--sender-host`
in `STRING_FLAGS`, per the brief) suppresses it unconditionally and silently, same as the local case. No
carve-out by kind or recipient: verified `--to ben` and ledger-only ACK/FYI both mirror.

## The open question (section 4) — decision and reasoning

`note-flush.mjs:1512`'s `runOverdueAsks` calls `runNoteSend` directly for its own BLOCKED nudge sends —
a genuinely new send, not a retry, and outside L1's file territory to change. Contracts R3 requires
"the outbox or retry code path never calls the mirror dependency," and names note-flush among the paths
that must never mirror.

**What I found and did**: `note-flush.mjs`'s outbox retry and `drainQuietly` never call `runNoteSend`
at all — they call `deliverToInbox`/`twoPhaseSend` directly (confirmed by reading transport.mjs and
note-flush.mjs's imports, matching the scout's finding) — so those two paths are safe by construction,
with no code of mine touching them. I wrote `R3: the piggyback drain (deps.flush) is a separate call
from the mirror` against `deps.flush` — the one place inside `runNoteSend` a drain call is injected (used
for the piggyback drain at send time) — and confirmed it is called independently of, and never
internally reaches, `deps.spawnMirror`.

For `runOverdueAsks`'s own nudge-send specifically (which DOES go through `runNoteSend`): I implemented
the sender-host/mirror logic exactly as specified in sections 1-3, with **no special-casing** for "am I
being called from note-flush." There is no clean signal inside `runNoteSend` for that (contracts R1/R2
name no such flag, and I was explicitly told not to add one to note-flush.mjs even if I concluded one
was needed). In practice, a nudge-sending process run by note-flush has no `SSH_CONNECTION` set (it's
not an ssh session) and passes no `--sender-host` argv element, so `resolveSenderHost` returns
`{host: null, sawAddress: false}` — the plain-local case — and the mirror never fires for it. This
matches the brief's own instruction (section 4) verbatim; I did not deviate from it.

**Flag for the reviewer/lead**: if "never from note-flush" in R3 meant something stronger than "in
practice it resolves local, so it doesn't fire" — e.g. a structural guarantee independent of what env
vars happen to be set on the flusher's process — this design does not provide that guarantee. A future
note-flush invocation that (for some unrelated reason) runs under an ssh session with `SSH_CONNECTION`
set, or is passed `--sender-host` by some future caller, WOULD mirror. I judged this an acceptable,
narrow residual risk given the brief's explicit instruction and the out-of-territory constraint, but it
is worth a second look before this is treated as fully closed.

## Deviations / assumptions

  `node:child_process.spawn` directly with a 5 s kill timer, matching the scout's note that async
  `execFile` has no `input:` option) exists for production use but is never exercised by any test — no
  live ssh is ever run, per the brief.
- Added `--sender-host`/`--no-mirror`/`--append-ledger` to the CLI's own `--help`/USAGE text inside
  note-send.mjs (not one of the two named SKILL.md spots, but the same file already in territory) so
  `--help` stays accurate; this is additive prose only, no behavior change, and I flag it here since it
  wasn't explicitly asked for.
- `mirrorLedger` is computed and attached to `base` (not built separately per branch), so it is present
  on the dry-run return path too only for the `unknown-sender-address` case (computed independent of
  whether a spawn happens); for a genuinely remote host in dry-run, the `plan` array carries the
  host/command info instead of a speculative `ok`/`error` that hasn't happened yet.
