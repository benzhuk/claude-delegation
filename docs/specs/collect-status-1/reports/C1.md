## Deviations from a literal reading of spec.md (all judgment calls, none touching pinned contracts)

1. **status.json carries three fields spec.md's shape-line doesn't name**: `fetch`
   (`"ok"|"skipped"|"failed"`), `changeKey`, and `announced`. spec.md:27 lists 5 top keys
   (generatedAt, host, repo, main, rows, summary) then, in the same paragraph, spec.md:32 says the
   collector "records the key it announced in status.json as `announced`" — so `announced` is
   explicitly required even though the shape-line doesn't enumerate it; I added `changeKey` beside
   it because comparing runs needs a persisted "this run's own key," which is not necessarily the
   same value as `announced` once a fetch failure or `--quiet` has diverged the two. `fetch` is an
   addition for symmetry with the md header's mandatory "fetch: failed" — harmless, but not named
   in spec's status.json shape line, so I flag it as a deviation rather than assume it away.
2. **Gate command**: this build's task text names
   `node --test scripts/collect-status.test.mjs scripts/collect-from-origin.test.mjs` directly;
   C1.md's own "Gate:" line names `node scripts/run-tests.mjs scripts/collect-status.test.mjs >
   docs/specs/collect-status-1/reports/C1-gate.log 2>&1`. I ran the outer task's literal command
   and redirected its output into the brief's named log path, then also ran the brief's sealed
   variant as a cross-check (both green, reported above). I did not edit either file to resolve
   the discrepancy — flagging it here for the lead.
3. **`--to` missing**: spec.md never states what happens if `collect-status.mjs` itself is invoked
   without `--to` while a note would otherwise be sent (C2's spec line 49 makes `--to` mandatory
   at the *installer* level, which is a different file). I chose to treat it exactly like a missing
   note-send binary — skip the send, say `note: skipped, --to missing` in status.md, still update
   `announced` — rather than block the whole write. This keeps the collector's core promise (a
   status file always gets written, exit 0 always) intact even when misconfigured.
4. **60-line budget**: buildStatusMd never truncates. For the realistic case (a handful of active
   lanes) this stays well under 60 lines (tested at 5 branches: header + attention + table = far
   under budget). Contracts.md's own attack brief names "a status.md over 60 lines on a 40-branch
   fixture" as something a reviewer should check for — I did not build a 40-branch fixture or a
   truncation mechanism, because spec.md's text ("then the table exactly as formatTable prints it")
   names no truncation rule to implement, and inventing one un-pinned would itself be an
   interpretation contracts.md doesn't authorize. Flagging this as open rather than guessing.
5. **`announced` update policy for `--quiet` / missing-note-send / missing `--to`**: contracts.md
   K2 only pins the fetch-failure case ("does not update announced"). For the other three
   "attempted but not actually dispatched" cases, I chose to still update `announced` to the
   current key — the intent (read from spec.md:38's parenthetical "for tests and for a first run
   on a new host") is that these are one-time/operational conveniences, and NOT updating
   `announced` would mean the very next real run re-sends immediately for a state already seen,
   defeating the point of a quiet first run. This is my own interpretation where contracts.md is
   silent; flagging it rather than treating it as pinned.
