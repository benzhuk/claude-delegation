# Lead rulings, collect-status-1 (win over spec.md where they differ)

spec.md here is skills-fable's spec copied byte for byte from origin/docs/lane-specs-0925 at 02b6156. Two rulings by skills-fable are fixed and not reopened: the collector sends RESULT only, at most one per change key. The lead's rule paragraph is pinned by a fixture test when one fits, and is otherwise a stated goal.

## K1 Paths (the C1/C2/C3 seam, pinned)
- Collector output, the default `--out`: `~/.agents/collect/<basename of the resolved --repo>/` holding `status.json`, `status.md` and `previous.json`. For this repo that is `~/.agents/collect/claude-delegation/status.json`.
- The collect job's installer marker is its OWN file, `~/.agents/collect/installed.json`, never the janitor's `~/.agents/janitor/installed.json`. The janitor file keeps its bytes whatever the collect job does. That is how "installed.json records both jobs by name" is met: one name-owned file per job. Shape, key order fixed: `{"schema":1,"repo":"<abs>","node":"<abs>","every":<int minutes>,"scheduler":"systemd-user"|"schtasks"|"launchd","name":"collect-status","to":"<slug>"}` followed by a newline.
- The collect job's run log is `~/.agents/collect/last-run.log`, truncated every run, as the janitor's is.
- C3's wiring check: `file` = `~/.agents/collect/claude-delegation/status.json` (literal, with `~` as the janitor check uses it, since the check type does not expand a basename), `maxAgeSeconds` 2700, `requiresFile` = `~/.agents/collect/installed.json`.

## K2 The note (C1)
- The sender slug is `collect-<host>`, where host is `--host` if given, else `os.hostname()` lower-cased, with every character outside `[a-z0-9-]` replaced by `-`, runs collapsed, trimmed, and cut to 40 characters. A host that sanitizes to nothing is `collect-host`.
- note-send is resolved as `~/.local/bin/note-send` if it is an executable file, else `note-send` on PATH, and is run with an argv array (spawn, never a shell string). The exec is injectable for tests.
- The note text is built only from integers and state tokens from a fixed allowlist: the collect-from-origin state names. Branch names, record paths and any origin-supplied string never enter `--text` or `--goal`. `--goal` is `status at <absolute status.md path>`, and the path must pass the envelope rules too. If it does not (for example a home path containing a forbidden character), drop the goal and still send.
- The change key is computed and compared exactly as the spec says. A run whose fetch failed sends no note and does not update `announced`: a failed fetch never wakes anyone.

## K3 Installer (C2)
- `--job collect-status` requires `--to <slug>`, with the slug validated by the same pattern note-send uses for slugs. `--every` must be an integer from 5 to 60, default 15. Every cross refusal and bound in the spec applies. `--remove --job collect-status` removes only files carrying the collect job's own marker line, plus `~/.agents/collect/installed.json`.
- The default job's generated bytes and installed.json are unchanged. The existing byte-stability tests pass without any edit to their expectations. A builder who needs to edit one has found a defect in their own change.

## Process
- Builders never run `rm`, `rm -rf` or `git clean`, and never delete anything, their own scratch included. Tests clean up only through the existing makeTempHome helpers.
- Attack brief, every reviewer: a crafted branch name or record field reaching the shell, the systemd or launchd text, or the envelope. Two hosts' collectors double-waking one lead (rule it: each host has its own slug and its own change key, so two installs mean two wakes. The lead installs on Netcup only. Say whether anything stops a second install). A fetch failure sending a note. A `--job` default drifting any existing byte. A check that passes because it isn't looking: a never-writes assertion that never exercised a write path, or a status.md over 60 lines on a 40-branch fixture.
