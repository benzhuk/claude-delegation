## Final pinned rulings

- Registration remains the proposal's exact version1 shape at AGENTS_HOME/ws/decisions-pickup/registrations.json, 1–16 entries, at most64KiB, regular/not symlinked. ALL entries must validate before any reader/send, including existing registeredProject binding. Page must normalize to32hex. Reject duplicate normalized pages OR canonical repos. Absolute real reader must be regular, not symlinked, and outside every Git checkout (reuse detectedGitRoot). No owner/project/reader/auth discovery. File presence is explicit host opt-in; no activation by builders.
- API: `runRegisteredPickup(options = {}, deps = {})` in decisions-pickup.mjs. options.registrationPath is an explicit test/injected path; production always uses the conventional path. Reuse filesystem/environment/time seams, add injectable selectIndex(count), default crypto.randomInt, and optional pickupOnce seam. Return ONLY `{code,ordinal}`, ordinal null before selection or selected zero-based index of stable canonical entry ordering. Choose ONE entry per pass randomly; no process fanout, persisted cursor or minute-slot rotation. State expected rather than guaranteed fairness; no N-minute maximum.
- Safe codes: PICKUP_UNCONFIGURED, PICKUP_DISABLED, PICKUP_CONFIG_INVALID, PICKUP_NO_ACTION, PICKUP_RECORDED, PICKUP_PENDING_OWNER, PICKUP_RECONCILIATION_REQUIRED, PICKUP_CLAIM_HELD, PICKUP_FAILED; host admission adds PICKUP_SKIPPED_BUDGET. Builder must explicitly map every existing status/receipt state in source and report. UNKNOWN, legacy, orphan, invalid evidence and owner mismatch are visible reconciliation/failure, never success. Unknown return maps FAILED. Preserve WAITING_OWNER's existing explicit owner-binding behavior; do not add reassignment or stale-claim cleanup. No private content, paths, page IDs, titles, owner names or raw exception messages in safe summaries/output.
- API: `runPostFlushPickup(argv, context, deps = {})` in note-flush.mjs. Context supplies completed normal flush result and elapsedMs; deps allow sealed filesystem/environment/clock/importer tests. Return null for excluded/unconfigured invocations, otherwise safe summary. Only standalone CLI invokes it AFTER successful normal flushing. Both normal manual CLI and timer opt in through registration; imports/piggyback/note-send/note-notify never invoke it. Help/status/dry-run/--to/--home, including equals forms, must not inspect registration. Reject nondefault AGENTS_HOME relative to actual/injected homedir rather than mixing state and transport homes.
- Preserve normal flush stdout, exit, peer accounting and delivery behavior. Elapsed >=30000ms skips pickup. Absent registration costs one existence probe, no dynamic import, registration read, page/receipt/transport access or extra write. Off switches precede registration reads and new work. Registered path dynamically imports the existing sibling pickup module; no new runner/CLI/scheduler.
- Remove the top-level-await cycle: note-flush CLI must call main through a non-top-level-await promise continuation with equivalent exit handling. A REAL subprocess test must invoke registered note-flush with actual relative imports and sealed reader, proving pickup ran and exit0 without deadlock/exit13. Import-only tests do not cover this.
- Correct budget claims: --no-type skips note-send's preliminary drain entirely and queues the wake. Only reader has its existing15-second limit. Git/filesystem/ledger time is not hard bounded. The30-second cutoff is admission, not cancellation or total runtime. Do not kill/race receipt transitions or add a recovery engine. Scheduler serialization/page claims remain existing protections.
- Observability uses ONLY optional `pickup:{at,code,ordinal}` in existing flush-last.json, with actual observation timestamp and fixed safe codes. Preserve a prior VALID annotation across ordinary/piggyback heartbeat replacement, without triggering pickup; corrupt annotations are not propagated. After registered attempt, atomically annotate only if the current heartbeat still belongs to this CLI pass (pid plus captured at/timer identity). Never overwrite newer peer accounting from another pass. This is dated diagnostic evidence, not authorization, delivery proof or a selection cursor. No extra status/history file. No fresh pickup time or fabricated success when registration is absent. --status --json exposes annotation; existing peer-flusher staleness/exit semantics stay unchanged. Observation write failure cannot break delivery; optional stderr contains only allowlisted codes.
- Keep recorded, delivered and acted-on distinct. RECORDED means ledger/wake queue; the NEXT normal flush uses existing inbox transport/escalation. Only explicit account records owner handling. No automatic Done clearing or inference of new authority.
