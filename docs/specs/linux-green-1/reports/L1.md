## Reviewer findings applied

### Finding 1 (MAJOR): the UNC-start branch skipped normalisation, a Windows regression from base and
a contract R2 gap

At `ffc882f`, `transport.mjs:447` read:
```js
c = isUNC(start) ? `${base}/${c}` : toPosix(path.posix.normalize(`${base}/${c}`));
```
The UNC branch avoided the `//`-collapse landmine by skipping normalisation entirely. When git returns
a `..`-relative common dir (e.g. `../../.git`, which git prints for `--git-common-dir` when run from a
subdirectory two levels deep), this left a non-canonical string
(`//host/share/repo/a/b/../..` instead of `//host/share/repo`) — a regression from base's canonical
Windows output, and a violation of contract R2's "normalised" requirement. The reviewer measured this
with a live import of `ffc882f` and a 19-case attack table; I re-measured it (see below) rather than
taking it on faith.

### Finding 2 (MINOR): an already-absolute common dir was used as-is, un-normalised

Same root cause, same patch: `c = normalise(c)` for the already-absolute branch was missing.

### The patch (applied verbatim, `transport.mjs:435-448` after the edit)

```diff

   const isUNC = (p) => /^\/\/[^/]/.test(p);
-  const cIsAbsolute = path.posix.isAbsolute(c) || isDriveLettered(c);

-      // `path.resolve` does not recognise a POSIX-relative-looking drive-lettered or UNC
-      // `start` as absolute, so it silently prefixes cwd). UNC's leading `//` must never
-      // pass through `path.posix.normalize`/`join`/`resolve` — they collapse it to a
-      // single `/` — so a UNC `start` is joined by hand, string-only, no such call.

+    c = toPosix(path.resolve(start, c)); // a genuinely relative `start`: cwd-relative is correct
```

## 2. `mainCheckout` fix — bug-fix fields

- **Cause:** `mainCheckout` composed a relative git-common-dir onto `start` with the OS-native
  `path.resolve(start, c)`. On Linux, `path.resolve` does not recognise a drive-lettered
  (`C:/...`) or UNC (`//host/share`) `start` as absolute — it treats it as a plain relative segment
  and silently prefixes the process cwd, producing `<cwd>/C:/Users/...` instead of the intended
  `C:/Users/...`.
- **Discriminating check:** whether `start` (after backslash-normalisation via `toPosix`) is
  POSIX-absolute, drive-lettered, or UNC. If so, compose onto `start`'s own string (never the
  process cwd); only a genuinely relative `start` still goes through `path.resolve` (cwd-relative is
  correct there — unchanged from before).
- **Fix location:** `skills/multi/scripts/transport.mjs`, inside `mainCheckout`, the composition
  block that previously read
  `if (!path.posix.isAbsolute(c) && !/^[A-Za-z]:/.test(c)) c = toPosix(path.resolve(start, c));`
  — replaced with an explicit branch on whether `c` is already absolute (POSIX/drive-lettered,
  unchanged: used as-is) versus whether `start` is POSIX-absolute/drive-lettered/UNC (compose onto
  `start`, string-only for UNC to avoid the `path.posix.normalize`/`join`/`resolve` UNC-`//`-collapse
  landmine the scout flagged; `path.posix.normalize` otherwise) versus a genuinely relative `start`
  (unchanged `path.resolve` fallback).
- **Simplification:** none applied beyond what the fix itself required — the function stays pure
  over strings apart from the existing git `runner` call, no new imports, and the two pre-existing H6
  tests are byte-identical (their expected outputs are unchanged; the diff is exactly one new test
  block).
