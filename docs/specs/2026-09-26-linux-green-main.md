## Why
The sealed suite on origin/main fails two tests on Linux and passes them on Windows. The lead's Netcup runner confirmed it at b7ddf11 with two full runs and isolated reruns, deterministic both times; the janitor-fed lane saw the same two at 5140db2. Every Linux-built lane since has either not noticed or explained the two away, and 0.20.12 went onto Netcup and Hetzner with them failing. A suite that is red on two of four hosts is not a gate; it is noise, and the second-host rule of the standing merge grant (Linux for a Windows-built lane) cannot be honoured while it stays red.

Both tests were written on Windows and assume it:

1. `skills/multi/scripts/note-send.test.mjs`, "H6: a plain checkout resolves to itself, and backslashes are normalised (L1)". On Linux the actual value is `<cwd>/C:/Users/benzh/Code/Zhuk Projects`. Cause, in `mainCheckout` in `skills/multi/scripts/transport.mjs`: the git runner returns `.git`, which is neither POSIX-absolute nor drive-lettered, so the function calls `path.resolve(start, c)`; on Linux `path.resolve` does not recognise `C:/...` as absolute and prefixes the process cwd. The function is meant to be pure over POSIX-normalised strings; it should compose the two strings itself (`path.posix` join and normalise when `start` is POSIX-absolute or drive-lettered) and only fall back to `path.resolve` for a relative `start`. That is a code fix, not a test fix.
2. `skills/multi/scripts/mirror-shim.test.mjs`, "V4: a real install writes one shim per command, each naming ITS OWN command in its errors", assertion "SKILL_FILE_EXCLUDE let a .test.mjs file publish". `scripts/mirror-shared-skills.mjs` publishes by copy on Windows and by symlink elsewhere (its own header says so, line 24; `MODE` at line 88). Under a symlink the mirrored skill directory is the repo directory, so a recursive read finds the repo's own `.test.mjs` files; SKILL_FILE_EXCLUDE can only act in copy mode. The test's own comment says the check is about what a copy landed. That is a test fix: assert the exclusion on copy mode (Windows, or a forced copy mode if the script exposes one; grep for how 1f65ca3 tested "both publish modes"), and on symlink mode assert instead that each skill entry under `~/.agents/skills` is a symlink into the repo and that no copied file exists beside it.

Measures: work lost or stalled (a red gate on two hosts hides real failures and stalls merges that wait for a second-host run), rework after acceptance (no lane re-litigates these two). Must not worsen: top-tier tokens per build (this lane is one builder, one reviewer).
