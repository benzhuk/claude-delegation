## The rule to write (docs, verbatim intent — word it in your own prose, matching each
file's existing voice)

When the record on origin says accepted, its Opus verdicts are in its evidence, and the
sealed suite is green on a second host from origin (a Windows host when built on Linux, a
Linux host when built on Windows — the lane lead runs it through ssh as a prior lane did,
or asks the spec lead), the lane lead merges its branch into main with a merge commit and
pushes, then posts ONE Closed entry on the owner's decisions page through the decisions
skill's existing anchored-edit route (`notion.js edit --safe`), then sends RESULT. No
Waiting item is posted for an ordinary accepted merge.

Closed-entry shape (a plain bullet, never starting with bold — `skill-text.test.mjs`
enforces no line anywhere in decisions SKILL.md may start with `**`):
`Merged <branch> at <sha>, <M-D>: <one-line changelog>; suite <n> of <n> on <host>.`

Releases and installs to the owner's machines stay per Ben's own word: the release item
remains a decision, with the merged changelog lines as its evidence. Say this in ONE
sentence in both `team-build/SKILL.md` and `decisions/SKILL.md`.

Conflicts (R3): ANY conflict when merging into main — not just a non-additive one — means
no merge; post a Waiting item with the conflicting paths instead. When `origin/main` is
not an ancestor of the branch tip, the merge result is a new tree: run the sealed suite on
the merge commit (at least the lead's own host, no new failing test name vs main) before
pushing main.

Done-window write rules (R5, red-team F1 — add this as new prose in `decisions/SKILL.md`,
near the existing pickup/registered-pickup material, since it protects that mechanism):
feeding registered pickup (which reads this same page) wedges once lane leads write the
page during an open pickup round, unless these three rules hold:
1. The owner lead's first write in a pickup round clears Done; it then handles items from
   the saved capture (`open`) plus fresh reads, then runs `account`.
2. A lane lead whose own fresh read shows Done checked does NOT write the page itself; it
   puts the Closed entry verbatim in its RESULT instead, and the owner lead posts it after
   clearing Done.
3. Every round ends with `account`, or later Done ticks wake no one.
Plus one sentence: the pickup host is the host where the owner lead's inbox lives
(`note-send` delivers only on the recipient's own host) — so registering pickup on the
wrong host silently dead-letters the wake.

Second-host evidence (R4): the second-host gate log is committed as record evidence
BEFORE `accept` runs (any record change after `accept` needs a fresh check) — say this in
the team-build sentence. The second-host condition is marked `(not checked)` in house
