## 2. Wiring check
`scripts/wiring-check.mjs` reads `scripts/required-wiring.default.json` (+ optional `~/.agents/required-wiring.json`) and evaluates 9 checks (wiring-check.mjs:1-30, full file read). Per-type outcomes: `json_value`/`hook_present`/`hook_absent`/`file_exists`/`file_absent`/`file_fresh` can be `missing`/`stale`/`unknown`; `switch`/`env_presence` are always `info`. `checkWiring().ok = results.every(r => state ok|info)` (wiring-check.mjs, near end of `checkWiring`). **But `main()`'s CLI always `return 0`** except an unknown flag (comment at file top: "Exit 0 always... a wiring check never fails its caller"; code: `return 0;` at the end of `main()`, only `--line`/`--json` gate what prints). So `ok:false` never surfaces as a process exit — a caller checking `$?` sees success regardless. Today's actual list (`required-wiring.default.json`) has only 2 checks that can ever report non-ok (`flusher-heartbeat`, `file_fresh`/info-on-missing; `lean-rules-file`, `file_fresh`); the other 7 are `switch`/`env_presence`, which are `info` by construction and can never fail. Ran it live on this host (via janitor's embedded WIRING section, same code path): `flusher-heartbeat ok`, `lean-rules-file ok`, all switches `info`.
`scripts/mirror-shared-skills.mjs --dry-run --json` is an installer, not a wiring health check: its `ok`/exit code (`process.exitCode = main()`, returns `refusals.length === 0 ? 0 : 1`, mirror-shared-skills.mjs near end) reflects install-time refusals (bad flags, unsafe symlink targets) — not whether an already-installed hook/shim is still correctly registered. `scripts/codex-hook-trust.mjs` is a library used to *write* Codex hook trust, not a checker (no CLI `main`/`process.exit` in the file).
`docs/reports/release-02013-report.md` (SCRATCH): the 0.20.13 install ran `mirror-shared-skills.mjs --codex-hooks-only --dry-run --json` and plain `--dry-run --json`/`--json` on all 4 hosts, checking only `ok`/action-count/refusal-count — `wiring-check.mjs` was never invoked as part of the install verification on any host.
Conclusion: a broken wiring condition covered by the current list (e.g. a stale flusher heartbeat) IS detected structurally (`state` would flip to `stale`), but nothing downstream ever turns that into a failing exit code or a build gate — `wiring-check`'s own CLI is contractually exit-0-always, and the install pipeline doesn't call it at all. "Wiring check cannot go red" holds.

## Proposal
**Goal "cleanup has an owner":** smallest change is one per-host scheduled entry (systemd `--user` timer on Netcup/Hetzner, Task Scheduler task on Windows, launchd on Mac — same primitives already assumed for note-flush) that runs `janitor.mjs --record` (report-only, no `--apply`) once daily, appending to the existing `docs/work/evidence/janitor/drift.md`/`<date>-<host>.json` files, which Ben's page already links. Rides on: the `--record` flag that already exists and is tested; no janitor code change needed, only an install step (extend `mirror-shared-skills.mjs` or a new installer) to create the 3 platform-specific timer/task definitions. Unverified: whether Ben wants `--apply` ever scheduled (brief and hard-stops say never do this automatically) — assume report-only forever.
**Goal "wiring check can fail":** smallest change is to (a) drop wiring-check.mjs's blanket `return 0` and exit 1 when `checkWiring().ok` is false for any non-`info` state, and (b) add that call (`node wiring-check.mjs || exit 1`) to `mirror-shared-skills.mjs`'s own install run so a broken install is visible immediately, not just printed. Rides on: `checkWiring()`'s existing pure `ok` boolean (wiring-check.mjs) — no new detection logic needed, only wiring the existing signal to the CLI's own exit code. Unverified: whether any existing caller relies on wiring-check's current "never fails" contract (its own doc comment says so deliberately) — changing it may need a version bump/changelog note and re-running `scripts/wiring-check.test.mjs`.
