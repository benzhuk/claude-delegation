## Seam contract between J1 and J2 (pinned)
- On a real install, J1's installer creates `~/.agents/janitor/`. It then writes `~/.agents/janitor/installed.json`, which must be byte-stable for the same inputs:
  - `{"schema":1,"repo":"<abs repo path>","node":"<abs node path>","hour":<int>,"scheduler":"systemd-user"|"schtasks"|"launchd","name":"janitor-record"}`
- `--remove` deletes `installed.json` together with the entries the installer made.
- The scheduled command is exactly `<node> <pluginRoot>/scripts/janitor.mjs --record --repo <repo>`, plus `--host <name>` if J1 adds that flag. Output goes to `~/.agents/janitor/last-run.log`, truncated on every run. The string `--apply` never appears anywhere.
- J2's `file_fresh` check on `~/.agents/janitor/last-run.log` (26 h) behaves as follows:
  - `installed.json` absent: state `unknown`, never `missing`.
  - `installed.json` present and the log absent: `missing`.
  - log older than 26 h: `stale`.
  - otherwise: `ok`.
  - The home dir is injectable, as the existing checks already allow.

## J1 rulings
- **Names:**
  - systemd user units `janitor-record.service` and `janitor-record.timer`, under `$XDG_CONFIG_HOME/systemd/user`, or `~/.config/systemd/user` when that variable is unset.
  - Windows task `janitor-record`; tests use `--name janitor-record-test`.
  - launchd label `com.delegation.janitor-record`, in `~/Library/LaunchAgents`.
- **Scheduling commands.** The installer never shells out to systemctl, schtasks or launchctl unless `--enable` is given. Unit and plist generation and file writes are pure. With `--enable`, it runs the host's enable/load command and prints it. Tests never pass `--enable`.
- **Node path.** Resolve it to an absolute path at install time (`process.execPath`). The systemd unit sets `Environment=PATH=<dir of node>:/usr/bin:/bin`.
- **Temporary checkout.** Refuse to install from a plugin root that is not the installed plugin cache, or from a temp dir. Mirror whatever refusal scripts/codex-hook-trust.mjs (or the Codex hooks installer the scout finds) uses. `--force-root` is allowed only in tests, through an env or arg the test sets.
- **`--remove`** removes only files whose content carries the installer's own marker line (`# generated by delegation install-janitor-timer`, or its XML/comment equivalent). A same-named file without the marker is left untouched and reported.
- **Repo path** comes from `~/.agents/janitor-repo` if that file exists. Otherwise it is `~/Code/claude-delegation`. `--repo` overrides both.

## J2 rulings
- The CLI's exit code is 1 when `ok` is false. Before changing it, list every caller (grep for `wiring-check` and `checkWiring`) in the report, and confirm none depends on the exit code or greps stdout in a way the change breaks.
- A settings file that is unreadable or not valid JSON gives state `unknown` with a reason, never `ok`.
- `hook_present` must match a real hook entry by its command string in the parsed JSON. It must not match a text search that a commented-out, disabled or different-command hook could satisfy. The scout names the exact settings file(s) and hook commands the plugin registers.

## Rules for every agent
- Never run `rm`, `rm -rf`, `git clean` or any other deletion in the shell. Two builders this week stalled 40 minutes and 19.5 hours on a deletion approval nobody saw. Tests clean their own fixture dirs through node's fs APIs inside the test process. For scratch space, use a fresh directory name.
- Tests use fixture homes only. Never write to the real `~`, never enable a real timer or task, and never run the janitor with `--apply`.
- Never set a git identity (no `-c user.*`, `--author`, `GIT_*` env or `--no-verify`), and add no commit trailers.
- A nested `claude -p` session must have `ORCA_TERMINAL_HANDLE` and `NOTE_SLUG` unset in its environment. None should be needed in this lane.
