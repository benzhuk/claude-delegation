## Territory C1: the collector (scripts/collect-from-origin.mjs, its test, fixtures)
1. `node scripts/collect-from-origin.mjs [--repo <dir>] [--main origin/main] [--json]` runs `git fetch` (or `--no-fetch`), lists every `origin/*` branch other than main and protected names, reads `docs/work/*.record.md` files that exist on that branch and not identically on main (or exist with a different `Status:`), and prints one row per branch: branch, tip sha and date, record path, `Status:`, `Artifact:` sha, whether the artifact is an ancestor of main (merged), hours since the record's last `Log:` line, and a state word: `accepted-unmerged`, `accepted-merged`, `owned` (in progress), `rejected`, `no-record`. Exit 0 always; `--json` prints the same as an array. At most 60 runtime lines; if it needs more, split what does not fit into a finding, not code.
2. Reads only through `git` plumbing (`for-each-ref`, `show`, `merge-base --is-ancestor`, `log -1`); never checks out, never writes. Pinned by a test with a bare-remote fixture holding three branches: accepted-unmerged, accepted-merged, owned.
3. `docs/census.md` (or the bearings skill's evidence template if that is the better home; pick one and say why) gets three sentences: the collector is run before any lane dispatch and at every merge tick, its table goes into the bearings packet, and "in flight" may only be written about a lane whose origin record says `owned`.

1. Team-build's acceptance step gains one rule: after `accept --census` and the push, the lane lead posts the merge item for its branch to the owner's decisions page itself, through the decisions skill's existing anchored-edit route and the decision-item template (title `Merge <branch> into main (<tip sha>)`, evidence line with the four numbers from the record, options merge-now / merge-and-release / hold, `No default: merges to main take your word per item`), and only then sends its RESULT. The lead who wrote the spec verifies the item exists on the page instead of waiting for a note.
2. The decisions skill states the shape for a lane-posted merge item in one paragraph and that two writers never edit the page at once (fresh read, one anchored edit, reader check, retry once on a changed anchor).
3. Codex lanes: state plainly whether the Codex mirror of the decisions skill can post the item; if it cannot yet, the Codex lane's RESULT carries the merge item text verbatim and the collector still finds the branch. Unsupported stays explicit.
