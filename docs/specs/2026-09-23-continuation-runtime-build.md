# Bounded continuation at the existing completion boundary

Build decision: Ben explicitly repeated ongoing useful building with maximum parallelism after the lead stopped again. Source construction and disposable native-runtime tests are authorized. A missing host observation is a test task, not a blanket blocker. Prior standalone read-only checker remains rejected; this build connects the scope binding and accounting to the real existing hook caller.

## Outcome and limits

An explicitly bound ongoing lead cannot silently finish with an unaccounted selected work snapshot without one bounded corrective opportunity. A model turn already doing useful work pays no additional model call. Explicit stopped/finite scope, positive child, unknown host identity, unbound scope, recursion, off switch, duplicate event and unchanged accounted snapshot produce no continuation block. Existing peer delivery remains independent and preserves emit-before-ACK.

One opportunity is not guaranteed sustained diligence. No unattended scheduler, idle self-message, automatic owner takeover, second work ledger, or universal SDK claim. Do not activate unsupported host profiles. Native normal/block/re-fire/cancellation fixtures determine supported profiles; mocks must generate provider responses, not fake hook events.

## Territories

- Runtime core: `scripts/continuation.mjs`, `scripts/continuation.test.mjs`; extends existing work-record parser/validator via imports. Owns per-session invocation binding, selection, revision and policy, CLI bind/status/account/stop. One high-tier integrity builder.
- Existing adapters: `hooks/multi-codex-hook.mjs`, `hooks/multi-inbox.js`, `hooks/multi-hook-core.mjs` and their tests. Owns verified role normalization, optional continuation invocation independent of peer slug, one composed output, after-flush semantics. Starts against committed core interface after scout/spec review.
- Parent: spec, contract, work records, manifest, skill caller documentation, integration and publication. Independent reviewer tests the final authority/identity/race boundaries.
- Native probes: temporary Codex and Claude fixtures in parallel. No changes to real configuration/auth/peer cursors. Their traces qualify each host capability and correct unsupported assumptions.

## Shared contract to pin after spec review

`handleContinuationEvent({ host, event, sessionId, turnId, role, stopHookActive, cancellation, cancellationVerified, input }, deps)` returns `null` or `{ context?, reason?, diagnostic?, afterFlush? }`. `role` is lead/child/unknown. `cancellation` is true/false/unknown from evidenced runtime behavior, never guessed fields or prompt keywords. `cancellationVerified` is a host capability established from native fixture/source evidence, not a user setting that magically proves behavior. Continuation exceptions must not swallow peer notes. Existing output is merged into one JSON object; existing peer ack IDs stay exactly unchanged.

Core exposes one normalized event seam for adapters and its tests, plus CLI functions. Source CLI `bind` names exact host/session, canonical integration repo, selected roots and an existing authority reference. It requests ongoing scope from existing user authority, never grants permissions. No ambient cwd/pane/old Owner/GOALS inference. Bind must be associated with current native event identity before it can block; supplied arguments alone are insufficient. `status` does not mutate; `stop` disarms explicitly; `account` records the exact selected revision and existing evidence reference, never copied task states.

## Binding and lifecycle

Keep invocation metadata in one local atomic file under existing AGENTS_HOME/ws/continuation, keyed by hashed host/session. No raw prompts/transcripts/Notion content. Existing work records remain sole work state. All mutation is serialized with a short exclusive claim; contention yields unknown/no block, no waiting/stale-lock theft.

A new authenticated user prompt immediately suspends an existing active binding. Its epoch must distinguish newer prompts from a stale asynchronous bind/account. The model reaffirms ongoing scope in the current turn when the new request is steering/status, or leaves it stopped/finite. Unknown freshness must fail closed. A positive child never touches parent state. SessionStart/resume without established latest-prompt identity suspends instead of rearming stale authority. Explicit bind observed by an exact matching current host event can activate the episode; future adapter implementation must name the evidence used.

UI interruption/cancellation is distinct from semantic user stop. An automatic block requires actual supported-host evidence that interruption bypasses Stop or exposes a trustworthy cancellation indication. Missing proof disables the block only for that host profile; source code and other supported profiles can still proceed.

## Selected work and progress

Read only explicitly selected root IDs and their Children closure in the bound integration checkout. Reject missing/duplicate singleton or work IDs, malformed required fields, cycles, unsafe paths, and moved/unreadable roots. Bound scans/bytes. Reuse existing parser and validator; report unknown instead of zero. Unrelated historical records must not become selected work.

Preserve runnable/owned/delivered/rejected/reviewed/blocked/accepted categories. Owned means someone is recorded as owning work, not proven live/dead; never steal/restart it. Blocked prose is evidence to evaluate, not proof every useful direction is blocked. All accepted/empty/no-ready never means goal achieved. One explicit scope reconciliation can account for this state through existing Next/Evidence/Observed work records.

Compute a deterministic revision from selected record content and authority evidence. Account only against a still-current revision and current episode, with a real existing evidence reference. Stale accounts must not suppress changed work. No per-tool rescan: work selection occurs on explicit account and eligible Stop. Do not interpret routine ACK/FYI as continuation work.

## Bound cost and delivery

At most one automatic corrective attempt per authenticated user episode; native stop_hook_active also bypasses before scans. A changed record during correction cannot trigger an endless new block. Reserve the attempt atomically before output; a crash leaves an uncertain consumed attempt and never automatically resends. New user authorization can establish a new episode. No polling, sleeping, waiting on peers, provider calls or queues in the core.

Combine a continuation reason with an existing peer Stop block in the same output. Peer-only block can carry the work accounting delta but cannot cause two correction turns. Failed continuation work must not alter peer output/ACK behavior. A previously accounted unchanged snapshot is silent.

## Acceptance

Independently test actual adapters with no peer slug, child and unknown identity, stale async rebind after newer user stop, prompt duplicate/reorder, moved repo, missing/cyclic/duplicate selection, accepted-only root, all-owned/all-blocked, changed revision, simultaneous Stop, emit failure, off-switch access error, and peer output/ACK composition. A test must fail when selected work is ignored or unknown is reported complete.

Native probes must separately show actual installed CLI normal completion, one block, correction re-fire and controlled cancellation with synthetic local provider responses. Preserve exact versions and sanitized field traces; do not turn fixture success into useful-model/outcome improvement. Once source and host evidence pass, run the real harness on already authorized work and measure intervention count, unnecessary turns, missed work and accepted results. Unknown total tokens remain unknown.

## Pinned red-team resolution

The source interface is `scripts/continuation-contract.mjs`. Runtime core imports/re-exports this vocabulary; adapters import the core's handleContinuationEvent only. Required normalized episodeKey/eventKey are adapter-evidenced, never CLI-supplied. A profile cannot block with a null/unknown episode key or unproved cancellation behavior. Scope CLI bind/account/stop REQUIRE the opaque expectedEpoch issued to the current lead by its native prompt hook; they must not discover/substitute the newest epoch for the caller.

The core observes authenticated prompt identity and emits a compact epoch context in that existing model turn. Duplicate eventKey/episodeKey is idempotent; old/reordered or unknown identity suspends rather than rearming. Bind is pending until an actual matching PostToolUse from that episode confirms it. Every eligible Stop must match the exact episode, including after intervals where off switches suppressed events. SessionStart/resume invalidates prior arming. An actual native structural user-message identifier can serve as episodeKey if the probe proves prompt/tool/Stop correspondence; never manufacture a missing Claude turn_id. Unsupported profiles remain nonblocking while supported ones progress.

At Stop the adapter first collects the existing peer result, then passes peerWillBlock into the core's atomic reservation. Any peer block consumes the valid bound episode's same opportunity even for accounted or unreadable work. A continuation exception never suppresses peer output or its exact after-flush ACK IDs. afterFlush can only mark its own still-matching reserved attempt emitted, never rearm or mutate a cursor.

Use bounded explicit record reads with parseRecord/validateRecord; listRecords swallowing I/O errors is not acceptable for deciding completion. Reject duplicate singleton fields before parsing. Account evidence must be attached to selected work and its content contributes to the revision. All state writes revalidate epoch/generation under a synchronous short claim; non-Stop timeout races cannot leave a late stale write. No claim is held while awaiting peer I/O.

Native fixtures are test processes; loopback server must remain on a live event loop while the CLI runs (async spawn, not spawnSync in the HTTP-serving process). Runtime tests must demonstrate request arrival before attributing startup failure to the SDK.

Claude's actual UserPromptSubmit precedes transcript persistence. The prompt event may issue an epoch while episodeKey is null; that alone never arms. Bind returns `continuationBind:{requestId,epoch}` in successful CLI JSON. For this profile, only the actual matching native PostToolUse carrying that pending requestId and current user UUID can activate, under the same epoch/generation claim. Adapters extract the marker from tool output, not arbitrary shell text. Later Stop rereads the current native user UUID and must match the armed UUID. Codex can use proven same-turn association when available. `Interrupt` is an explicit Codex event and disarms matching state without producing output or another turn.

Primary contracts fetched during this build: https://code.claude.com/docs/en/hooks#stop documents that user interruptions do not fire Stop; https://learn.chatgpt.com/docs/hooks documents Codex Interrupt and Stop's continuation prompt. Native fixture evidence remains necessary for the actual implementation. Independent Claude SDK tests proved interruption during inference and an in-flight delayed Stop hook creates no extra Messages request; a cancelled Stop may still exit zero with terminal_reason stop_hook_prevented, so generic success codes do not establish cancellation absence.
