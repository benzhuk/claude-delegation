Source files, all under `docs/decisions/` on main, plain markdown:
- `now.md`: the "What is going on" paragraph, three to five sentences (a sentence ends at `. `, `? ` or `! ` outside a markdown link), lead-written, replaced whole.
- `session.md`: the "This session" bullets, at most eight, each at most 200 characters, lead-written, replaced whole; first line `since: <ISO>`. Only `publish --clear-done` sets `since:` (to the round's captured tick time); nobody edits it by hand.
- `waiting/<slug>.md`: one open decision item each, exactly the `templates/decision-item.md` shape; removed when the decision closes (its closing bullet goes to the day's history file in the same commit).
- `history/YYYY-MM-DD.md`: append-only, one file per New York day; first line after the heading is `Summary: <one sentence>` (the History bullet on the page). Everything that used to go into Closed goes here as a plain bullet in the same commit as the merge or the answer: the merge line, an owner's note or question with its answer in the form `Your note, <M-D>: "<full text, verbatim>" — <answer>`, a closed decision with what was chosen and the observed result.
- `last-render.md`: the step-6 READBACK bytes of the last publish (what Notion returned, not what the renderer produced: Notion rewrites `~` to `\~` and autolinks bare file names, see history/2026-09-27.md). Written, committed and pushed by `publish` itself.

Normalisation, one function used by every comparison in this lane: CRLF to LF, strip trailing whitespace per line, collapse runs of blank lines to one, drop one trailing `<empty-block/>`; nothing else (anything looser would hide a tick or a comment).

`decisions-render.mjs render --repo <dir> [--done-line <text>] [--drop-owner-lines <file>]` prints the page: `# Waiting on you now` (every `waiting/*.md` in file order, or `Nothing right now.`), `# What is going on` (now.md), `# This session (since your tick at <Day H:MM AM/PM>)` (session.md, `since:` converted to America/New_York), `# History {toggle="true"}` (one bullet per history file, newest first: `[Mon D](https://github.com/benzhuk/claude-delegation/blob/main/docs/decisions/history/YYYY-MM-DD.md) — <Summary>`, then one bullet per archive file, then `<empty-block/>`), the comment callout, the Done line (`--done-line` verbatim, else `- [ ] Done`), `<empty-block/>`. Render refuses with exit 2 naming file and line when: a line outside a `<summary>` starts with bold; text outside a URL or a quoted owner note matches a token of 7 to 40 hex characters containing at least one letter and one digit; session.md breaks its two limits; now.md breaks its sentence limits; a history file lacks its Summary line; a history or archive file linked on the page is absent from `git ls-tree origin/main` (a 404 link never publishes); a waiting item fails `decisions-read.mjs` (SHAPELESS or missing options). Acceptance test: the render output parses with `decisions-read.mjs` exit 0, zero warnings, `DONE false`, and nothing but blank follows the Done line (the pickup's DONE_NOT_LAST rule, decisions-pickup.mjs:399).

`decisions-render.mjs publish --repo <dir> --page <id> [--clear-done] [--adopt-live] [--dry-run]`, in order:
1. Fresh read of the page to a temp file.
2. Owner input on the fresh read (`decisions-read.mjs`: any escaped `\*\*` comment line, a ticked Done, a ticked option). Without `--clear-done`: any owner input → exit 3 "owner input pending: run the pickup, then publish --clear-done". With `--clear-done`: this publish is the pickup round's FIRST write (SKILL.md:96-99 requires Done cleared before account). It requires (a) a captured pickup round for this page whose capture lists exactly the owner inputs the fresh read shows (read through decisions-pickup.mjs's existing status output; a mismatch is exit 3 naming the difference), and (b) every owner line's full text present verbatim inside today's `history/` file (or the waiting item it answers). Only then does the render drop those lines and emit `- [ ] Done (last cleared: <now, America/New_York>)` and set `session.md since:` to the round's tick time (committed with last-render.md in step 8). Without `--clear-done`, step 4 copies the fresh Done line verbatim. Test both paths.
3. Drift: the fresh read, normalised, must equal `last-render.md`, normalised. Otherwise exit 4 with the diff and this message: "the page was written outside the renderer. An agent line (a legacy Closed bullet or an anchored edit) is moved verbatim into today's history file, then publish again; a line Ben wrote goes through the pickup. If the diff equals the fresh read versus the newest notion.js backup for this page, the last publish crashed after writing: rerun with --adopt-live." `--adopt-live` writes the fresh readback as `last-render.md` (step 8) and logs it; it never skips step 2.
4. Render with `--done-line` from the fresh read (or the cleared line under `--clear-done`).
5. `notion.js replace-md` (the ONE sanctioned caller for this page; the backup path it prints is logged).
6. Fresh readback; `decisions-read.mjs` exit 0 and no normalised diff against the render, else exit 5 naming the backup to restore from.
7. `decisions-title.mjs set --topic <topic from project config>`.
8. Write `last-render.md` from the step-6 bytes, `git add`, commit `chore: decisions page published <ISO>`, push to main; on non-fast-forward, fetch, rebase this one commit, push again (the file is publisher-owned, so the rebase never conflicts on content); a second failure is exit 6 with the page already updated and the commit left on a branch `render/last-<ISO>` for the caller. Exit 0 only after the push. `last-render.md` lives in the repo, not in notion.js's backup dir, because that dir is host-local (notion.js:285-288) and the next publisher may be on another host. Git is the lock: a second publisher on another host sees a page that no longer equals its `last-render.md` and exits 4; its caller fetches main (now holding the first publisher's commit), re-renders, republishes. No lock file.
`--dry-run` stops after step 4 and prints the page.
