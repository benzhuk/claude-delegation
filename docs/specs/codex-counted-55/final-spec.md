## Temporal completeness and support

Known-id discovery records discovery.scope={kind:'canonical-session-tree',complete,reason}; legacy fallback states kind:'default-horizon' and existing horizonUtcDays. Complete means the finite configured directory walk and relevant identity graph were readable/verified at the read snapshot, not a promise about future files or inaccessible machines. The canonical tree's role and limitations are explicit in text. Capture metadata sufficient to show the read snapshot, not transcript content.

For each selected file contributing to the requested bounded historical window, temporal completeness requires intact metadata/JSON and either a valid timestamped row beyond --to, or a final task_complete row with the matching turn_id for the most recent task_started. Thus a still-running lead can support an earlier closed window. A later child created after --to with no in-window rows does not make that historical window partial. A relevant file ending before --to with an open task, a malformed/truncated row, known rotation gap or missing window timestamps is incomplete. Report PARTIAL with the concrete temporal reason and observed subtotals. Detect damaged Codex rows locally without changing Claude's parser. Preserve usable prefix evidence; never guess a missing row or timestamp. No end-bound witness means an open/unbounded active run remains PARTIAL.

Keep field support separate from temporal completeness. Existing native input includes cache; derived total remains native input+output, not input+cache+output. Incomplete usage prevents a whole combined token aggregate: retain observed subtotals and null/unavailable complete totals. Existing consumers four-read/work-record must not start treating missing values as complete because a label changed. Preserve existing JSON keys and meaning: lead.coverageSupported and combined must remain conservative for their legacy token-consumer purpose. Introduce a separate Codex report verdict/status only where necessary to let text say COUNTED for supported complete-window fields while field-specific unsupported tokens remain unavailable downstream. COUNTED is never a blanket all-fields or all-hosts assertion. No four-read.mjs edits.

Native leadTurns counts distinct valid task_started.turn_id events in the selected window; responses/observedLeadRequests count distinct response ids. Preserve both. Do not substitute 99 responses for Lane52's one native turn or vice versa. Wakes and Stop-blocks use the existing verified host-event/marker parser, with unavailable if the relevant host contract lacks evidence.
