## Temporal completeness and support

Known-id discovery records discovery.scope={kind:'canonical-session-tree',complete,reason}; legacy fallback states kind:'default-horizon' and existing horizonUtcDays. Complete means the finite configured directory walk and relevant identity graph were readable/verified at the read snapshot, not a promise about future files or inaccessible machines. The canonical tree's role and limitations are explicit in text. Sessions whose metadata proves a different root are excluded. The census and codex-rows.md explicitly state that counted scope is the lead's own session graph and excludes shell-launched codex exec runners and other hosts' agents. Capture metadata sufficient to show the read snapshot, not transcript content.

For each selected file contributing to the requested bounded historical window, temporal completeness requires intact metadata/JSON and either a valid timestamped row beyond --to, or a final task_complete row with the matching turn_id for the most recent task_started. Thus a still-running lead can support an earlier closed window. A later child created after --to with no in-window rows does not make that historical window partial. A relevant file ending before --to with an open task, a malformed/truncated row, known rotation gap or missing window timestamps is incomplete. Report PARTIAL with the concrete temporal reason and observed subtotals. Detect damaged Codex rows locally without changing Claude's parser. Preserve usable prefix evidence; never guess a missing row or timestamp. No end-bound witness means an open/unbounded active run remains PARTIAL.

Keep field support separate from temporal completeness. Add lead.codex.fields mapping with stable keys: model, inputTokens, cachedInputTokens, cacheWriteTokens, outputTokens, reasoningOutputTokens, derivedTotalTokens, leadTurns, responses, wakes, stopBlocks, stallNudges, stalls. Each is {status:'COUNTED'|'UNSUPPORTED',reason:null|string}. COUNTED is an exact supported observation, including a justified zero; missing or invalid evidence is UNSUPPORTED for that field, never a default zero. Existing native input includes cache. reasoningOutputTokens is a subset of outputTokens as Codex reports them, verified against the token_count schema in a fixture. derivedTotalTokens = inputTokens + outputTokens; never re-add reasoning or cached tokens. Preserve per-model optional null/unavailable values and dedupe by logical session plus response id with conflict rejection. Never sum cumulative snapshots.

Unknown model permits exact response/input/output totals where present, but model attribution and top-tier allocation remain unsupported. Incomplete usage prevents a whole combined token aggregate: retain observed subtotals and null/unavailable complete totals.

The line-1 prefix `VERDICT: COUNTED ` is printed if and only if the census is temporally complete: discovery.scope.complete is true and every selected file is time-complete for the requested window. Unsupported fields do not block COUNTED but are listed on line 1 as `; UNSUPPORTED <field>[, <field>]`. Preserve existing line-1 wording `<n> Codex responses (leadTurns <m>)` byte for byte. Otherwise print PARTIAL with concrete reasons. Accepting COUNTED with UNSUPPORTED fields is intended; state this in docs/census.md. Run the untouched work-record suite, which accepts COUNTED and refuses PARTIAL.

lead.coverageSupported is true if and only if temporal completeness holds and inputTokens, cachedInputTokens, outputTokens, model and derivedTotalTokens are all COUNTED. Codex has no cache-write tier: combined[model].cache_creation_input_tokens is 0 with fields.cacheWriteTokens COUNTED only if the native log format proves no such tier exists; otherwise null and UNSUPPORTED. Preserve the existing consumer keys. No four-read.mjs edits. codex-rows.md takes each token and turn cell from four-read output when available and census JSON otherwise, naming the source in every cell. COUNTED never asserts all-field or all-host coverage.

Native leadTurns counts distinct valid task_started.turn_id events in the selected window; responses/observedLeadRequests count distinct response ids. Preserve both. Do not substitute 99 responses for Lane52's one native turn or vice versa. Wakes and Stop-blocks use the existing verified host-event/marker parser, with unavailable if the relevant host contract lacks evidence. Ledger nudges retain existing bounded ledger definition and provenance. Native Agent/Task/Workflow stall attribution remains UNSUPPORTED unless this log actually supplies the established required fields; response gaps stay explicitly separate heuristics.
