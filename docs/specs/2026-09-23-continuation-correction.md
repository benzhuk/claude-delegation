# Preserve ongoing work across status and wave completion

User finding: the orchestrator ended after six source territories shipped and a partial native trial, despite explicit continuous-work authorization and useful remaining lanes. Existing goals and continue instructions already prohibited that stop; the failure was applying the rule only on explicit resume instead of at the shipping/reporting decision.

Goal: finish useful authorized work with maximum useful parallelism, respecting project scope and actual external boundaries. This correction applies when an ongoing goal is authorized, not to expanding a finite one-off request.

## Territory and change contract

One mid-tier builder owns only skills/continue/SKILL.md, skills/team-build/SKILL.md and skills/delegate/SKILL.md. Parent owns records/release metadata and the live follow-through lanes. No scripts, scheduler, framework, runtime hooks, repeated policy blocks or new goal store.

Keep the decision procedure canonical in continue. Its discovery description must cover ongoing execution and wave/turn closeout, not only resuming after a pause. Replace/reorganize overlapping prose rather than appending a second full policy.

Before ending an ongoing goal turn or declaring a wave complete, reconcile current goal/acceptance evidence, owned work, pending reviews/integration, known remaining requirements, and actual external blockers. Select and start independent ready useful work; refill available disjoint capacity. If the ready queue is empty while goal outcomes remain unmet, inspect those outcomes and their dependencies to find finite useful work or establish concrete blockers. This is bounded project work, not invented busywork or recursive expansion.

A shipped release, exhausted wave, failed trial or status reply is not a global stop condition. User status questions receive a concise progress update while active work continues unless the user explicitly pauses/stops/changes scope. One blocked dependency does not block independent useful lanes. Preserve explicit user limits and authority; elapsed time or an unanswered question grants nothing.

Only stop when requested, the authorized objective has evidence of completion, or every remaining useful authorized item has an actual external dependency. Record those specific dependencies and resumption inputs through existing records. Do not impose a ceremonial report at every tool call or promise autonomous wake capability.

Team-build must route from ready releases/review closeout back to this continuation decision without waiting for all unrelated work to finish. Delegate synthesis/reporting must do the same for ongoing goal work. Keep those caller instructions short and reference the canonical skill rather than copying it.

## Evidence

Validate three skills with existing skill validator. Independent reviewer should evaluate concrete scenarios: shipped wave with ready native work; one denied trial and independent source gap; status question during a running build; empty queue with unmet scoped goal; genuinely all-external blockers; completed finite one-off request; explicit user stop. Reviewer should decide and justify next action from the changed skill instructions, identify ambiguity/overreach, and report exact source revision. This is behavioral review evidence, not proof the runtime will always comply. No tests that merely assert added words.

Use this real patch as the useful mixed-provider review pilot where possible. Parent can capture a native review's final text without requiring reviewer file-writing. That is attributable review output, not evidence of native write permission or installed discovery.
